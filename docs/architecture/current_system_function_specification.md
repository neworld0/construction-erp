> 기준: 2026-08-25 코드 분석 결과. 기능 ID는 본 문서 관리용이며, 화면 URL·권한은 실제 URLConf와 View의 권한 검증을 기준으로 운영한다.

| 역할 | 주 업무 | 범위 |

## 3. 화면/처리 상세 정의

### 3.1 FIELD

| 화면군 | 핵심 동작 | 결과 |
|---|---|---|
| 진행률 | 전일 값 복사, 임시저장, 제출, 승인 후 정정/취소 요청 | `DailyProgress`, 소급/정정 요청 |
| 보고서 | 현장보고와 증빙 업로드 | `FieldReport`, `Evidence` |
| 원가 입력 원본 | 원가 입력 시 일자·CBS·메모 생성 | `DailyReport`, `DailyReportLine`, `CostActual` |
| 원가 | CBS 검색, 발생일·금액·증빙 입력 | `CostActual`/Line, 승인 큐 |

| 창고 조회 | 현장 및 필요한 본사 창고 재고/원장 확인 | 읽기전용 재고 가시성 |

## 4. 비기능·운영 요구사항

| 항목 | 정의 |
|---|---|
| 권한 | 역할, 법인 멤버십, 프로젝트 배정을 결합해 검증한다. URL 직접 입력은 UI 숨김의 대체가 아니며, 신규/변경 View·API는 이 세 범위의 회귀 검증 대상이다. |
| 감사 | 금전·승인·마감·정정·파일다운로드의 행위자, 시각, 대상, 사유를 AuditLog에 남긴다. |
| 데이터 보존 | 계약/단가/기성/매출/급여는 시점 스냅샷을 보존하여 이후 마스터 변경이 과거 금액을 바꾸지 않게 한다. |
| 마감 | 일반 수정은 차단하고 승인된 정정만 반영한다. |
| 개인정보 | 주민번호·계좌·급여는 화면/다운로드 최소권한, 마스킹 및 별도 접근감사를 적용한다. |
| 가용성 | FIELD는 모바일 우선 입력, HQ는 PC 좌측 메뉴·대기 큐 중심, CEO는 KPI 중심으로 제공한다. |

## 5. 현재 구현의 후속 관리 항목

1. Generic FK 정정대상에 대한 정기 무결성 점검을 운영 배치로 추가한다.
2. 실제 회계 분개/부가세 신고는 ERP 집계와 별도 회계 시스템의 원장 대사 정책을 명문화한다.
3. 기존 데이터의 법인 귀속이 불명확한 경우 자동 추정하지 않고 `NEEDS_REVIEW` 목록으로 관리한다.
4. 모든 신규 기능은 법인 범위·마감·감사·반려 재작업·모바일 표시 회귀 검증을 통과해야 한다.

## 6. 문서 검증 정정 이력

- `DailyReport`를 진행률 또는 독립 승인 대기 기능으로 해석한 표현을 제거했다. 이는 원가 입력의 보조 원본이며, HQ 홈의 독립 승인 대기 집계 대상이 아니다.
- `DailyProgress`의 반려 수정이라는 표현을 제거했다. 원본 상태값은 `draft/submitted/approved/voided`이고, 승인 후 변경은 `ProgressCorrectionRequest`로 관리한다.
- 권한 검증을 모든 화면/API가 이미 완전 충족한다는 단정 대신, 실제 설계 원칙과 회귀 검증 요구사항으로 표현을 정정했다.
