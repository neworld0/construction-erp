# 공사일보·월 정산 확장 기능정의서 v1.6

> **v1.6 출력 기능:** 모든 공사일보 화면은 `인쇄`와 `PDF 다운로드`를 제공한다. PDF는 한글 보고서 형식으로 전일·금일·당월 누계 및 작업 내역을 출력하며, 호출 당시의 RBAC·법인·프로젝트 범위 검증을 다시 수행한다. 다운로드 자체는 AuditLog의 원천을 수정하지 않는다.

> **v1.5 보고서 화면 요구:** 기준일 D에 대해 전일(D-1), 금일(D), 당월 누계(월초~D)를 동일 원천·승인 조건으로 계산한다. 단일 프로젝트 화면은 금일 작업 내역과 원천 목록을 보여주고, HQ/CEO 취합 화면은 프로젝트별 금일 업무 요약과 누계를 함께 보여준다. 장비·물량처럼 현재 원천이 없는 항목은 임의 수치로 표시하지 않는다.

> 범위: 고기근린공원 공사일보와 7월 정산서에서 확인된 업무 항목을 기존 ERP에 연결하기 위한 기능 정의. 이 문서는 구현 승인 전 기준이며, 코드·마이그레이션을 포함하지 않는다.

> 정밀 검증 반영: V-01~V-07 전체. 특히 진행률 계산방식, 마감 후 정정, 거래처 지급계좌, 원가 중복, 마감 잠금의 규칙은 정밀 검증 보고서를 기준으로 한다.

> **v1.3 결정:** 공사일보는 별도 입력·제출·승인 객체가 아니라 기존 원천 입력을 표시하는 자동 취합 보고서다. 따라서 기존 `SiteDailyLog` 입력 모델, 물량행, 장비행, 별도 승인 큐는 채택하지 않으며, 원천 데이터의 승인·반려·마감 상태를 그대로 표시한다.

> **v1.4 메뉴·이력 정책:** FIELD의 `보고서` 탭과 모바일 보고서 작성 진입은 제거한다. `FieldReport`는 과거 이력 보존을 위해 삭제하지 않으며, HQ·CEO의 기존 승인함에서는 `기존 현장보고`로만 표시한다. 신규 일일 운영 보고는 공사일보 자동 취합 화면이 단일 진입점이다.

## 2. 공사일보

### DSL-01 프로젝트 공사일보 자동생성

| 항목 | 규칙 |
|---|---|
| 프로젝트, 법인 | FIELD는 배정 프로젝트만 선택. HQ/CEO는 허용된 법인과 프로젝트 범위만 선택. 계약 법인은 자동 표시 |
| 기준일 | 기본값은 오늘. 프로젝트 기간·월마감·소급입력 규칙을 적용하여 원천을 조회 |
| 생성 기준 | `프로젝트 + 기준일 + 보고서 버전`으로 계산. 사용자가 공사일보를 생성·제출하지 않음 |
| 표시 정보 | 진행률, 출역, 원가, 자재투입, 반입·재고, 기존 보고서·진행률 메모, 원천별 상태·작성자·승인자·기준시각 |
| 보완 메모 | 기존 원천으로 표현할 수 없는 현장 특이사항만 선택적으로 기록. 재무·재고·진행률·노무 원천을 생성하거나 변경하지 않음 |
| 첨부 | 기존 원천 Evidence를 링크로 표시. 보완 메모 첨부도 원본·해시·작성자·일시를 보존 |

### DSL-02 진행률·WBS 자동 집계

| 입력/표시 | 정의 |
|---|---|
| 작업 매핑 | HQ가 관리하는 `ProjectWorkProgressMapping`은 진행률 화면의 WBS·ScheduleTask 연결 기준으로만 사용 |
| 공종·규격·단위 | 승인된 진행률·WBS·계약내역에서 자동 표시. 보고서에서 임의 변경 불가 |
| 계획·전일·금일·누계 | 기존 `DailyProgress` 및 `ScheduleTask` 원천에서 계산하여 표시 |
| 진행률 영향 | 공식 진행률은 기존 진행률 승인 흐름이 단일 원천이다. 공사일보는 계산 결과를 재집계·설명할 뿐 진행률을 새로 승인하거나 생성하지 않음 |

- 하나의 `ScheduleTask`의 계산방식은 HQ 매핑 정책으로 관리한다.
- 공사일보는 진행률 원천을 대체하지 않는다. 물량형 진행률 자동화가 필요하면 별도 승인된 `DailyProgress` 생성 서비스가 해당 정책을 적용하며, 공사일보는 결과만 표시한다.

### DSL-03 인원 자동집계

- 동일 프로젝트·기준일의 출역부를 직종별·상태별로 자동 합산한다.
- 공사일보에서는 읽기 전용이며, 오류는 출역부 원천에서 정정한다.
- 직종별 `전일 누계`, `금일 공수`, `누계 공수`를 보여준다.
- 직원·반장·조경공·비계공 등 표시명은 `LaborRole` 기준으로 관리하며, 임의 텍스트 분류를 금지한다.

### DSL-04 자재·재고 자동 집계

| 항목 | 규칙 |
|---|---|
| 반입·투입·재고 | `InventoryLedger`, `IssueToWork`, 현장창고 재고에서 프로젝트·기준일로 자동 표시 |
| 품목·규격·단위 | ItemMaster/UoM 기준으로 자동 표시. 품목명 검색·CBS 추천은 자재 투입 원천 화면에서 수행 |
| 수량·단가·금액 | 원천의 승인·제출·임시저장 상태와 함께 표시하며 보고서에서 수정 불가 |
| 재고 반영·증빙 | 재고원장과 원천 증빙 링크를 표시. 공사일보 조회로 재고 또는 원가를 생성하지 않음 |

### DSL-05 원가·장비 자동 집계

| 항목 | 규칙 |
|---|---|
| 원가·장비 | `CostActual` 및 장비 관련 원가 원천을 프로젝트·기준일로 자동 표시 |
| 발생·증빙·VAT | 원천의 발생일, 증빙일, VAT 상태, 금액기준을 표시. 보고서에서 변경 불가 |
| 검증 | 누락·반려·마감·증빙 부족을 경고하고 원천 상세로 연결 |

### DSL-06 법인·그룹 취합 공사일보·대사

- HQ는 선택 법인·기준일·프로젝트 범위의 모든 프로젝트를 하나의 취합 보고서에서 비교한다. 각 프로젝트 행은 진행률, 출역 공수·노무비, 원가, 자재 투입·재고, 원천 상태, 누락·반려 건수를 표시한다.
- CEO는 아산, 미산 또는 아미산(그룹합산)을 선택해 동일 기준일의 취합 결과를 열람한다. 그룹합산은 법인별 소계와 합계를 함께 표시하며 타 법인 쓰기 권한을 부여하지 않는다.
- 공사일보에는 독립 승인·반려가 없다. 원천 반려 사유와 승인자·승인일시를 표시하고 해당 원천 상세로 연결한다.
- 보고서 스냅샷은 월마감·기성·준공 대사의 근거로 보존할 수 있으나 비용지급 승인이나 CEO 결재를 대체하지 않는다.

### DSL-07 메뉴·드릴다운

| 사용자 | 메뉴 | 기본 화면 | 허용 동작 |
|---|---|---|---|
| FIELD | `공사일보` | 자신이 배정된 프로젝트의 일일 공사일보 목록·상세 | 기준일·프로젝트 선택, 원천별 상태 확인, 진행률/출역/원가/자재투입 원천으로 이동 |
| 법인 HQ | `공사일보·대사` | 선택 법인 전체 프로젝트 취합 보고서 | 기준일·프로젝트 필터, 누락·반려·불일치 확인, 원천 승인·정정 화면으로 이동 |
| 그룹 HQ | `그룹 공사일보·대사` | 권한 보유 법인의 병렬 취합 보고서 | 법인별 비교·합산 열람. 원천 수정은 각 법인 권한 범위에서만 가능 |
| CEO | `공사일보 현황` | 아산/미산/아미산(그룹합산) 취합 보고서 | 기준일·법인 필터, 프로젝트 상세·월정산·기성 대사로 드릴다운. 일일 원천 직접 수정 불가 |

## 3. 프로젝트 월 정산

### SET-01 프로젝트 월 정산서

| 구역 | 집계 기준 | 표시값 |
|---|---|---|
| 공사현황 | 계약/변경계약/실행예산 | 당초·변경·증감, 공급가/VAT/합계, 보험료, 실행율 |
| 기성·수금 | 승인 기성보고·수금·선급금 | 전회·당월·누계 기성, 선급금 수령/공제, 미수금 |
| 원가·손익 | 승인 CostActual + 아직 CostActual로 전표화되지 않은 승인 급여배부 | 직접/간접 원가, 원가율, 당월·누계 손익. 자재투입 생성 원가와 출역 집계액은 중복 합산하지 않음 |
| 미지급금 | 확정 발생원가 - 지급/직불 CashEvent | 거래처별 잔액·지급예정일·연체상태 |
| 현금흐름 | CashEvent | 예정/확정 유입·유출, 잔액 추정 |

### SET-02 미지급금 원장

- 원가 발생과 현금 지급을 독립적으로 관리한다.
- `PayableItem`은 거래처, 프로젝트, 법인, **발생일(`occurrence_date`)**, 증빙일, 세금계산서 공급일, 공급가액, VAT, 총액, 계정과목, CBS, 지급예정일, 지급수단, 발주처직불 여부를 가진다.
- 발생일은 재화·용역의 검수·사용이 확정된 날이다. 실제 지급일은 CashEvent/비용집행에서 별도 관리하며, 발생 원가의 귀속월을 바꾸지 않는다.
- 하나의 비용은 여러 차수 지급 및 일부 직불을 지원한다.
- 지급 취소·정정은 원지급을 삭제하지 않고 반대 거래 또는 Adjustment로 남긴다.
- 거래처와 지급계좌는 `BusinessPartner` 및 `BusinessPartnerPaymentAccount`에서 관리한다. 현재 CashAccount는 회사 소유 출금계좌이므로 거래처 계좌를 대체하지 않는다.
- `PayableItem.vat_status`는 `DEDUCTIBLE_CONFIRMED`, `NONDEDUCTIBLE`, `EXEMPT_OR_NONTAXABLE`, `PENDING_EVIDENCE` 중 하나로 관리한다.

### SET-03 자금청구

- 미지급금 또는 승인 비용집행 대상에서 자금청구 초안을 만들며, 중복 청구를 차단한다.
- 계좌 정보는 거래처 마스터에서 참조하고 화면·출력에서는 마스킹한다. 전체값은 재무 권한자만 복호화할 수 있다.
- 청구액은 공급가액/VAT/합계, 직불금액, 본사집행액을 분리한다.
- 승인 후 CashEvent와 지급 상태가 연계되며, 실제 지급일은 마감월 입력 제한과 무관하게 회계 정책상 해당 지급월에 기록한다.
- 발주처 직불은 자금청구의 회사 지급으로 처리하지 않는다. 실제 발주처 지급확인 후 SET-08 직불 정산으로 처리한다.

### SET-04 하도급 정산

- 하도급 계약·변경계약, 공종별 기성, 전회/당월/누계/잔액, 청구·지급·직불을 분리한다.
- 하도급사 원가와 일반 거래처 장비·자재비를 혼동하지 않도록 계약 연결 여부를 명시한다.
- 계약 법인과 하도급 계약 법인이 일치해야 하며, 타 법인 거래는 별도의 법인간 거래 절차가 필요하다.

### SET-05 계정과목 매핑

- 회계 계정과목은 `CostItem`/CBS와 다대다 매핑될 수 있으며, 프로젝트별 기본 배부 규칙을 둔다.
- 매핑에는 직접비/간접비, VAT 공제 가능 여부, 기본 비용유형, 허용 법인, 기본 증빙 요구사항을 포함한다.
- 공통비는 하나 이상의 CBS·프로젝트에 배부할 수 있으나, 배부기준·비율·승인자·시점이 필수다.

### SET-06 정산 출력·스냅샷

- 월마감 전에는 미리보기, 월마감 후에는 확정본 Excel/PDF를 제공한다.
- 정산서는 원천 거래 ID를 내부적으로 보유하고, 출력물에는 필요 최소한의 식별자만 표시한다.
- 기존 Excel은 조회·검증용 가져오기 대상으로만 사용하고, 외부 참조 수식 및 `#REF!`는 원천 데이터로 수입하지 않는다.

### SET-07 VAT 판정·증빙관리

| VAT 상태 | 원가 표시 기준 | VAT 신고 반영 | 필수 확인 |
|---|---|---|---|
| `DEDUCTIBLE_CONFIRMED` | 공급가액 | 매입세액 반영 | 적격 증빙·사업 관련성·세금계산서 확인 |
| `NONDEDUCTIBLE` | 총액 | 미반영 | 불공제 사유 |
| `EXEMPT_OR_NONTAXABLE` | VAT 없음 또는 총액 | 미반영 | 면세/비과세 근거 |
| `PENDING_EVIDENCE` | 잠정 총액 | 보류 | 증빙 수취·세무 검토 |

- 입력 시 공급가액·VAT·총액을 모두 보관한다.
- `PENDING_EVIDENCE`는 경영 원가에서 임의로 VAT를 차감하지 않으며, 월마감 시 미확정 건수·금액을 별도 경고한다.
- 일용노무·급여처럼 VAT가 없는 지급은 `EXEMPT_OR_NONTAXABLE`로 기록한다.

### SET-08 발주처 직불 정산

- `BillingSettlementAllocation`은 기성청구의 수금 정산을 기록한다. 유형은 `CASH_RECEIPT`와 `OWNER_DIRECT`다.
- `OWNER_DIRECT`는 `ProgressBilling`, `PayableItem`, 발주처 지급확인 증빙을 필수로 연결한다.
- 확정 시 기성 미수금과 협력사 미지급금을 같은 금액만큼 감소시키며, 회사 CashAccount/CashEvent는 생성하지 않는다.
- 직불 요청·예정 상태에서는 잔액을 감소시키지 않는다. 실제 지급 통보·확인 증빙 수취 후에만 확정한다.
- 직불 자체는 새로운 매출·매입 VAT를 만들지 않으며, 원 기성 세금계산서와 협력사 증빙의 VAT 판정을 그대로 따른다.

### SET-09 하도급 기성·청구·지급

- `SubcontractAgreement`는 하도급 계약금액, 변경금액, 선급금·기성공제·유보금 조건, 계약 법인, 협력사를 스냅샷으로 보관한다.
- **하도급 기성**은 현장/HQ 검수로 시공 실적이 확정될 때 발생하며, 해당 금액을 미지급금 원천으로 만든다.
- **하도급 청구**는 협력사 청구서·세금계산서의 수취 상태다. 기성 확정이나 지급 완료를 자동 의미하지 않는다.
- **하도급 지급**은 회사 지급 또는 발주처 직불이며, 미지급금을 감소시킬 뿐 새 원가를 만들지 않는다.
- 원수급인 기성청구와 하도급 기성은 서로 참고할 수 있으나 자동 동일 처리하지 않는다.

### DSL-07 마감 후 공사일보 정정

- [v1.3로 폐기] `SiteDailyLogCorrectionRequest`는 도입하지 않는다. 마감된 원천의 변경은 기존 진행률·노무·원가·재고 정정 요청을 사용하고, 공사일보는 승인된 결과를 재집계한다.
- 기존 값·변경안·사유·영향 예상치·요청자·승인 이력을 저장하며, 원본 일지를 덮어쓰지 않는다.
- 물량 변경은 연결된 `QUANTITY` 진행률과 기성·정산 영향 대사를 다시 실행한다. 재고·원가·현금 영향은 별도 Adjustment/원천정정으로 분리한다.

## 4. 공통 비기능 요구사항

| 영역 | 요구사항 |

| 권한 | 역할 + 법인 멤버십 + 프로젝트 배정의 세 조건을 View/API/다운로드에 동일 적용 |

## v1.2 개정 범위 — AI Layer 연계 준비(설계 전용)

이 문서의 v1.2 개정은 `Construction_ERP_AI_Layer_Implementation_Design_Pack_v1.3`의
법인 범위, SoR 단일권위, 금액 의미, Evidence·Claim 재현성, 승인·마감 보존 원칙을
공사일보·월 정산 확장 설계에 연결한 것이다. **이번 버전은 AI 호출, AI 테이블,
마이그레이션, 외부 Provider 연결, 기존 업무 화면의 코드 구현을 포함하지 않는다.**

- 기존 ERP 원천 시스템(SoR)이 계약·진행률·원가·재고·노무·기성·승인·마감의 유일한
  확정 권위를 가진다. AI/Ontology는 향후 읽기 전용 Context, Evidence, 설명·검토·초안에만 사용한다.
- 모든 향후 Context는 `legal_entity_id`, 범위(`PROJECT`/`LEGAL_ENTITY`/`GROUP`),
  사용자·역할·법인 멤버십·프로젝트 배정의 권한 스냅샷을 먼저 확정한다. 프로젝트 범위는
  반드시 해당 프로젝트의 계약 법인과 일치하고, GROUP 범위는 명시적 그룹 권한이 있어야 한다.
- 계약·기성·원가·현금·세금 Claim에는 `amount_basis`(VAT 포함/별도/해당없음), 통화,
  기준일, 계산 서비스, 원천 스냅샷 해시를 함께 보존한다. 기준이 없는 핵심 금액 Claim은 생성·적용하지 않는다.
- 재무·계약·세금·승인·마감에 관한 핵심 Claim은 Claim ID와 Evidence link를 반드시 가져야
  하며, Evidence가 하나라도 없으면 향후 AI 결과의 적용·제출은 `BLOCK`한다. 일반 서술문은
  별도 관찰 지표로 관리하며 확정 사실로 승격하지 않는다.
- AI 초안의 기술 상태와 기존 문서의 HQ/CEO 승인·반려·잠금 상태를 분리한다. 승인 단일권위는
  기존 업무 workflow이며, AI/ontology의 장애·비활성화가 기존 업무를 중단시키지 않는다.

## 5. v1.2 AI Layer 선행 호환 기능(설계만, 구현 보류)

| ID | 기능 계약 | 현재 단계 | 향후 수용 기준 |
|---|---|---|---|
| AR-01 | 법인·프로젝트 Context 계약 | 설계 | 모든 요청에 법인/범위/권한 스냅샷, PROJECT 법인 일치, GROUP 명시 권한 |
| AR-02 | SoR Adapter·금액 의미 사전 | 설계 | 계약·기성·진행률·원가·현금·세금의 실제 모델/계산 서비스를 필드별로 매핑하고 VAT 기준·기준일·해시 보존 |
| AR-03 | Claim–Evidence 계약 | 설계 | 핵심 재무·계약·세금·승인·마감 Claim은 ID+Evidence 1건 이상, 미충족은 BLOCK |
| AR-04 | 권한보존 Context 미리보기 | 설계 | 실제 생성과 같은 RBAC·마스킹을 적용한 redacted preview만 제공 |
| AR-05 | 승인·마감 단일권위 | 설계 | AI 초안은 기존 Approval/Closing/Adjustment workflow를 대체하거나 우회하지 않음 |
| AR-06 | 재현성·보존·장애 복구 | 설계 | Context/Evidence/Prompt/응답의 해시·보존기간·파기감사, outbox·idempotency, AI-off 수동 업무 가능 |

### AR-02 원천 매핑 최소 범위

| 업무 의미 | 향후 Adapter 후보 | 금지된 단순화 |
|---|---|---|
| 계약 | Project, ProjectContract, ContractSnapshot | 가상 `Contract` 한 모델을 확정 원천으로 가정 |
| 기성·매출 | BillingReport, ProgressBilling, OwnerConfirmation, TaxInvoice | 발주처 확정·세금계산서·수금 상태를 “기성 완료” 하나로 통합 |
| 진행률·일보 | DailyProgress, ProgressCorrectionRequest, SchedulePlan/Task, DailyReport | 승인 진행률과 원가 입력일보를 동일 Evidence로 간주 |
| 승인 | 기존 BillingReport 등 workflow | AI 초안의 상태를 법적/업무 승인으로 사용 |
| Generic 참조 | Evidence/Approval/Audit 공통 Resolver | 문자열 모델명과 ID만으로 권한 검증 없이 조회 |

이 절의 기능은 AI 기능을 지금 활성화하는 요구사항이 아니다. 실제 구현은 AI 레이어 전 선행
업무 구현과 정합성 검증이 끝난 뒤, 별도 Discovery·5-Layer Delivery Pack·승인 Gate를 통과한
단계에서만 시작한다.
