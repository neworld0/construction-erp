# 법인 면허·신용평가등급·공종 시공 실적 관리 Delivery Pack v1.1

기준일: 2026-08-27  
대상: HQ > 법인·면허 관리

## 1. FAST-CODEX Prompt

법인 단위 신용평가등급과 면허별 공종 시공 실적을 기준일 단위 스냅샷으로 관리한다. 신용평가등급은 평가기관·등급·기준일·유효기간·증빙 비고를 보관한다. 공종 실적은 선택된 운영 법인의 활성 면허로 제한하고, 면허·공종·기준일·3년/5년 실적·외부 공종 코드(선택)·출처·증빙을 보관한다. 실적은 ERP 내부 매출로 추정하지 않고 실적증명서·확인 자료 기준으로 관리한다. 실적증명서는 스냅샷별로 PDF·Excel·이미지 파일을 여러 건 추가 첨부하며, 기존 파일은 교체하지 않는다. 향후 입찰 API 연동 시 신용등급의 유효성, 공종 코드, 기준일 현재의 최신 실적 스냅샷을 참여 가능 여부 필터의 근거로 사용한다.

## 2. Discovery Contract

- 기존 `LegalEntityLicense`는 법인별 면허 소유·유효성의 원천이며, 프로젝트 계약 면허의 FK/M:N 참조가 있으므로 삭제·대체하지 않는다.
- 새 `LegalEntityCreditRating`은 법인 FK(`PROTECT`)를 갖는 신용평가등급 스냅샷 엔터티다. `LegalEntityLicenseConstructionPerformance`는 면허 FK(`PROTECT`)를 갖는 별도 실적 스냅샷 엔터티이며, `LegalEntityLicenseConstructionPerformanceEvidence`는 그 스냅샷의 추가형 증빙 파일 엔터티다.
- 현재 입찰 API의 공종 코드체계, 실적 산정 기준(관급·민간 포함 여부, 공동도급 지분, VAT 포함 여부)은 확정 자료가 없으므로 자동 산정 또는 API 적격 판정은 구현하지 않는다.
- HQ는 현재 선택된 법인 범위에서만 실적·증빙을 등록·수정·첨부한다. CEO는 동일 범위에서 조회·증빙 다운로드만 할 수 있으며, FIELD에는 진입·수정 권한을 부여하지 않는다.

## 3. Reproduction/Test Harness

1. HQ 사용자로 선택 법인 면허의 `도로·포장` 실적을 기준일 2026-08-31, 3년 1,000,000,000원, 5년 1,500,000,000원으로 등록한다.
2. 동일 면허·공종·기준일 중복 등록은 DB 제약으로 차단한다.
3. 5년 실적이 3년 실적보다 작거나 음수이면 폼 검증으로 차단한다.
4. 타 법인 면허 ID를 POST해도 해당 법인의 폼 queryset 및 서버 필터로 차단한다.
5. 유효 종료일이 평가 기준일보다 빠른 신용평가등급은 차단한다.
5. PDF·XLSX·XLS·PNG·JPG/JPEG 파일만 20MB 이하로 업로드되는지 확인하고, 원본 파일명·SHA-256·업로드자·시각이 보존되는지 확인한다.
6. 증빙 다운로드 URL에 타 법인의 파일 ID를 직접 입력해도 404가 반환되는지 확인한다.
7. 생성·수정·첨부·다운로드 후 AuditLog의 전후 스냅샷과 행 수가 일치하는지 확인한다.

## 4. Eval Gate / Promotion Criteria

- 법인 경계 밖의 면허·실적을 조회·저장할 수 없다.
- 면허·공종·기준일 조합은 하나의 스냅샷만 존재한다.
- 모든 금액은 0원 이상이며 동일 기준일에서 5년 실적은 3년 실적 이상이다.
- 목록에서 신용평가등급의 평가기관·등급·기준일·유효기간 및 실적의 3년·5년 금액, 출처, 기준일, 증빙·비고와 입력자를 표로 확인할 수 있다.
- 실적증명서는 여러 파일을 추가할 수 있고, 기존 파일을 덮어쓰거나 교체할 수 없다.
- 증빙 다운로드는 선택 법인 범위의 HQ·CEO로 제한되며, 실적·증빙 등록은 HQ만 할 수 있다.
- 프로젝트 면허 선택, 기존 계약 면허 스냅샷, 법인 권한 동작에 회귀가 없다.

## 5. Rollback & Operational Audit Checklist

- 배포 전 기존 법인·면허·프로젝트·계약 면허 참조 행 수를 스냅샷한다.
- 롤백이 필요하면 새 실적 테이블과 UI만 되돌리고 기존 면허 및 계약 데이터는 변경하지 않는다.
- 실적 정정은 행 삭제보다 수정 + AuditLog로 처리한다. 실적증명서 원본 또는 출처·기준일을 `evidence_note`와 첨부 파일에 남긴다. 파일 교체가 필요하면 기존 파일을 보존한 채 새 파일을 추가한다.
- 실제 입찰 API 연동 전에는 발주처별 공종 코드 매핑, 실적 산정 범위, 기준금액의 VAT 기준, 공동도급 지분 반영, 증명서 유효기간을 별도 승인한다.
