CODEX PROMPT — HQ Inbox 고도화 (승인함/리스크 카드/즉시 처리)

목표
/app/hq/ HQ 대시보드를 “요약 화면”이 아니라 **업무 처리용 승인함(Inbox)**으로 고도화한다.
•	승인 대기(일일보고/원가/변경요청/출역부/자재이동 등) 항목을 카드형 리스트로 표시
•	각 항목은 클릭 → 상세 이동 가능
•	일부 항목은 대시보드에서 바로 승인/반려(quick action) 가능 (권한 HQ만)
•	입력 시각/지연 시간 표시(24h/48h 하이라이트)
•	대기 항목이 0건이어도 카드 레이아웃 유지(“없습니다” 텍스트만 덩그러니 금지)
________________________________________

2) 데이터 소스(승인함 항목 정의)
다음 “승인 대기 큐”를 통합 리스트로 만든다.
A. 승인 대기 일일보고
•	DailyReport 또는 DailyReportLine (프로젝트/일자/작성자/상태)
•	상태가 SUBMITTED(또는 PENDING) 인 것만
B. 승인 대기 원가
•	CostActual 또는 DailyReportLine 중 COST 타입 (프로젝트/CBS/금액/작성자/상태)
•	증빙(Evidence) 누락 여부를 같이 표시(리스크 배지로)
C. 승인 대기 변경요청
•	ChangeOrder / WBS Change Request / PlanChangeRequest 등
•	상태 PENDING
D. 승인 대기 출역부
•	Timesheet 상태 SUBMITTED/PENDING
E. 재고 이동 승인(있다면)
•	Transfer 상태 SUBMITTED/PENDING
주: 프로젝트/모델 명이 실제 코드와 다를 수 있으니, 현재 프로젝트에서 “승인 대기” 상태를 가진 모델을 발견해 위 큐에 매핑한다.
“Discovery 후 매핑”을 우선 수행하고, 매핑 결과를 주석으로 남긴다.

3) Inbox UI 설계(필수)
HQ 대시보드 상단에 “오늘의 할 일” 요약, 그 아래에 승인함 섹션 3개(또는 1개 통합 탭)를 만든다.
3-1. 상단 요약 카드(Counts)
•	승인 대기 총 건수
•	24시간 초과(지연) 건수
•	Open Risk 건수(리스크 엔진이 있으면)
3-2. 승인함 카드(섹션)
섹션은 최소 아래 3개는 고정 렌더:
•	승인 대기 일일보고
•	승인 대기 원가
•	승인 대기 변경요청
추가로 출역부/재고 이동은 있으면 표시.
카드 표시 규칙
각 행(row)은 다음 정보 포함:
•	프로젝트명
•	유형(일일보고/원가/변경요청/출역/재고이동)
•	핵심값(원가면 금액, 진행률이면 %, 변경요청이면 요약)
•	작성자(필드 사용자)
•	작성일시(YYYY-MM-DD HH:mm)
•	지연 배지(>24h 노랑, >48h 빨강)
•	상태 배지(SUBMITTED/PENDING)
행 우측 액션:
•	[상세보기] (항상)
•	[승인] [반려] (Quick action 지원 모델만)
Quick action은 “원가/출역부/일일보고”만 우선 적용. 변경요청은 기존 상세 승인 화면에서 처리(대시보드에는 상세보기만).
________________________________________
4) Quick Action 구현(필수)
4-1. 엔드포인트
다음 엔드포인트 추가(POST만):
•	/app/hq/inbox/approve/
•	/app/hq/inbox/reject/
POST body:
•	object_type (예: DAILY_REPORT, COST_ACTUAL, TIMESHEET)
•	object_id
•	action (approve/reject)
•	reason (reject 시 필수)
4-2. 서버 처리
•	HQ 권한 체크 (RBAC)
•	마감(CLOSE-2) 이후면 승인/반려도 제한 규칙 적용(정책에 맞게)
•	기존 승인 로직 호출(ApprovalRequest가 있으면 생성/변경, 없으면 상태 변경)
•	AuditLog 남기기
•	redirect back to /app/hq/ with 메시지
4-3. UI 폼
•	각 row에 작은 form 버튼 2개(approve/reject)
•	reject 클릭 시 reason 입력 모달(간단히 prompt 또는 모달 구현)
•	CSRF 포함
________________________________________
5) 정렬/표시 정책
•	기본 정렬: (1) 48h+ 지연 먼저, (2) 24h+ 지연, (3) 최신순
•	각 섹션은 최대 5건만 표시 + “더보기” 링크 제공
o	더보기 링크는 기존 목록 페이지가 있다면 연결
o	없으면 /app/hq/inbox/?type=COST_ACTUAL 형태로 간단 목록 페이지를 추가(선택)
________________________________________
6) 빈 상태(Empty State) UX (필수)
대기 항목이 없더라도 카드 UI는 유지하고 아래처럼 표시:
•	“대기 항목이 없습니다.”
•	(보조 문구) “현장 제출이 들어오면 이곳에 표시됩니다.”
________________________________________
7) 완료 기준(Acceptance)
•	HQ 계정으로 /app/hq/ 접속 시
o	승인 대기 섹션이 카드 형태로 보이고
o	대기 항목이 있으면 row들이 표시
o	[상세보기] 클릭 시 기존 상세로 이동
o	[승인]/[반려] Quick action 동작 + AuditLog 생성
o	지연 배지가 24h/48h 기준으로 표시
o	대기 항목 0건이어도 UI가 깨지지 않음
________________________________________
8) 테스트 시나리오(간단)
1.	FIELD가 원가 1건 SUBMITTED 생성
2.	HQ 대시보드에 원가 1건 표시 확인
3.	HQ 대시보드에서 “승인” → 상태 approved 반영 확인
4.	다시 대시보드에서 목록에서 사라지거나 상태 변경 확인
5.	반려는 사유 필수 확인
