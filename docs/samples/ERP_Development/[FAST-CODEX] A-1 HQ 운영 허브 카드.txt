[FAST-CODEX] A-1: HQ 운영 허브 카드 (To-do + 바로가기 + 최근 승인) — HQ Dashboard


목표
- HQ 대시보드(/app/hq/) 상단에 “HQ 운영 허브” 카드(또는 섹션) 1개를 추가한다.
- 이 카드에서 HQ가 매일 하는 핵심 업무를 “행동 중심”으로 요약한다:
  1) 오늘의 To-do (승인/리스크/마감/누락)
  2) 승인함/주요 관리 화면 “바로가기”
  3) (옵션) 최근 승인 처리 내역 3건(AuditLog 요약)
- 기존 설계(승인/리스크/마감/권한/감사로그) 로직은 유지하고, “표시용 집계 + 링크 UI”만 추가한다.
- DB 스키마 변경 없이 구현한다.

전제(변경 금지)
- 기존 모델/상태/권한/마감(CLOSE)/감사로그(AuditLog) 로직 변경 금지
- 기존 URL 유지: /app/hq/
- N+1 쿼리 금지
- 리스크 등급화/분류 로직(C-1)이 이미 적용되었거나, 적용 예정임
  - 있으면 재사용
  - 없으면 “OPEN 리스크 수”만으로 degrade(추가 구현 없이)

구현 범위
- HQ dashboard view: hq/views.py (또는 현재 HQ 홈 view)
- 템플릿: hq_home.html (상단 헤더 영역 근처에 카드 추가)
- (권장) hq/todo.py : 집계/문구 생성/정렬을 담당하는 순수 함수 모듈

카드 UI 요구(필수)
- 카드 제목: “HQ 운영 허브”
- 좌측: “오늘의 HQ 업무(To-do)” 리스트(최대 5개)
- 우측: “바로가기” 버튼 그룹(기존 상단 버튼을 그대로 두되, 허브 카드에도 최소 3개만 제공)
- 하단(옵션): “최근 승인 처리” 3건 요약

1) 오늘의 HQ 업무(To-do) — 집계 항목(필수)
To-do 항목은 아래 4개를 기본으로 하고, 최대 5개까지만 표시한다.
각 항목은: 상태아이콘(🔴/🟠/🟢) + 문구 + 카운트 + 링크

(1) 승인 대기 처리
- 정의: HQ가 처리할 승인 대기 건수 합계
  - 대상 모델/큐는 프로젝트 기존 승인 체계를 그대로 사용(ApprovalRequest 중심이면 그것 사용)
  - 타입별(일일보고/원가/변경요청/출역/재고이동 등)이 있으면 합산 + (선택) 타입별 서브 카운트 표시
- 상태 아이콘:
  - 🔴 n>=5, 🟠 1~4, 🟢 0
- 링크:
  - HQ 승인함(Inbox) 페이지가 있으면 그 URL
  - 없으면 /app/hq/ (앵커 또는 tab 쿼리 사용 가능) 또는 가장 가까운 승인 목록 페이지

(2) CRITICAL/HIGH 리스크 확인
- 정의: OPEN 리스크 중 CRITICAL/HIGH 건수
  - C-1 리스크 카드 로직이 있으면 severity 기반으로 계산
  - 없으면 OPEN 리스크 전체를 HIGH로 취급하지 말고 단순 “OPEN n건”만 표시
- 상태 아이콘:
  - 🔴 critical>0
  - 🟠 critical==0 and high>0
  - 🟢 둘 다 0
- 링크:
  - HQ 리스크 목록 페이지(있으면)
  - 없으면 HQ 대시보드 리스크 섹션 앵커(#risks)

(3) 마감 임박/마감 상태 점검
- 정의: 월 마감(ClosingPeriod) OPEN 상태에서 “임박” 또는 “프로젝트 마감 충돌(CLOSE-4)” 관련 점검 필요 건수
- 구현 우선순위:
  A) ClosingPeriod에 due_date/close_date가 있으면 “D일 이내(기본 3일)” 프로젝트 수
  B) 없으면 “이번 달 OPEN + 미승인/미제출 잔존 프로젝트 수”로 대체(과도한 경보 금지)
- 상태 아이콘:
  - 🔴 임박>0
  - 🟢 0
- 링크:
  - 월 마감 관리 화면 URL(이미 상단 버튼 존재)

(4) 오늘 누락(미제출/임시저장 방치) 점검
- 정의: 오늘 기준, FIELD가 임시저장만 해두고 제출하지 않은 건(진행률/보고서/원가) 합계 또는 프로젝트 수
- 상태 아이콘:
  - 🟠 n>0
  - 🟢 0
- 링크:
  - 프로젝트 목록 또는 HQ 누락 점검 화면(없으면 /app/hq/projects/ 또는 프로젝트 목록 버튼 URL)

(5) (선택) 48h+ 승인 지연
- ApprovalRequest에 created_at/updated_at이 있으면 48h+ 대기 건수 표시
- 상태 아이콘: 🔴 n>0 else 🟢
- 링크: HQ 승인함(Inbox)

To-do 표시/정렬 규칙(필수)
- 가장 위험한 항목이 위로:
  1) 🔴 항목
  2) 🟠 항목
  3) 🟢 항목(가능하면 숨기거나 마지막)
- 단, “승인 대기”는 항상 첫 줄에 고정(업무 흐름상 최우선)

빈 상태(필수)
- 모든 항목이 0이면:
  - “🟢 오늘의 HQ 업무가 모두 정상입니다.” 문구 표시
  - To-do 리스트는 1~2줄만 유지하거나 접기

2) 바로가기(Quick Links) — 최소 제공(필수)
허브 카드 우측에 버튼 3~6개만 제공(기존 상단 버튼은 유지).
버튼 텍스트는 한글, HQ 실무 우선순위로 배치:
- [승인함 열기] (Inbox)
- [월 마감 관리]
- [프로젝트 목록]
- (선택) [CBS 관리], [창고 관리], [품목 관리], [출역부 승인], [급여 배부]
요구:
- 링크는 기존 버튼 URL을 그대로 사용(중복 구현 금지)
- 권한 없는 계정이면 버튼 숨김(예: HQ지만 기능이 비활성화된 경우)

3) 최근 승인 처리(AuditLog 요약) — 옵션(여유 시 포함)
- 카드 하단에 “최근 승인 처리” 3건을 표시:
  - 승인/반려/마감/정정/변경요청 승인 등 HQ가 수행한 액션 중심
- 데이터 소스:
  - AuditLog가 있으면 그것을 사용
  - 없으면 ApprovalRequest 상태 변경 내역으로 대체(단, 스키마 변경 금지)
- 표시 필드:
  - 액션명(승인/반려/마감/정정 승인 등)
  - 대상(프로젝트명 또는 object_type/id)
  - 시각(“10분 전”, “어제” 등 상대시간이면 좋고, 없으면 YYYY-MM-DD HH:mm)
- 링크:
  - 가능한 경우 해당 객체 상세로 이동
  - 링크가 없으면 텍스트만

성능 요구(필수)
- HQ 홈 로딩에 영향 최소화:
  - 승인 대기 카운트 1쿼리
  - 리스크 카운트 1쿼리(또는 이미 C-1에서 만든 컨텍스트 재사용)
  - 마감/누락 카운트 1~2쿼리
  - AuditLog는 최신 3건 limit 적용 + select_related

템플릿 변경 요구(필수)
- 기존 헤더 영역 아래(현재 상단 버튼 줄 근처)에 허브 카드를 삽입
- 다크 테마 스타일 유지:
  - 기존 card 클래스/컴포넌트 재사용
  - 과한 색상/애니메이션 추가 금지(뱃지는 기존 스타일 사용)

완료 기준(Acceptance)
- /app/hq/ 상단에 “HQ 운영 허브” 카드가 표시된다.
- To-do가 0/비0에 따라 상태 아이콘과 카운트가 정확히 표시된다.
- “승인함 열기” 등 바로가기가 동작한다.
- (옵션) 최근 승인 처리 3건이 보이고, 데이터가 없으면 “내역이 없습니다.”가 표시된다.
- DB 스키마 변경 없이, N+1 없이 동작한다.
- 기존 승인/리스크/마감 로직은 변경되지 않는다.

개발자 테스트(간단)
- 승인 대기 2건 생성 → To-do 첫 줄 🟠 “승인 대기 2건”
- CRITICAL 리스크 1건 생성 → 🔴 “CRITICAL 1건”
- 임시저장만 1건 생성 → 🟠 “오늘 누락 1건”
- 모든 0 → “정상” 메시지

위 요구사항을 만족하도록 구현하세요.
먼저 HQ 홈 view에서 기존 버튼 URL/집계 코드 위치를 찾아 재사용하고,
todo_items / quick_links / recent_actions 컨텍스트를 구성한 뒤 템플릿에 렌더링하세요.
