[FAST-CODEX] ATT-0: Attachment 표준(미리보기/링크/멀티업로드/임시저장 유지) 확정 + 한글 깨짐(UTF-8) 상시 점검 체계 구축

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 기존 설계 유지, 재설명 불필요
- DB 스키마 변경 없이 진행
- FIELD/HQ/CEO 화면 모두에 적용되는 “첨부(Attachment) 표시/링크 표준”을 먼저 확정하고,
  이후 ATT-1~ATT-5 구현의 기준점으로 삼는다.
- 동시에 최근 발생한 “한글 깨짐” 문제를 재발하지 않도록 ‘원인 스캔 + 방지 규칙 + 회귀 체크’를 이 티켓에서 고정한다.

목표(산출물)
A) Attachment UI/링크/권한/멀티업로드/임시저장 유지 “표준 정의(코드 주석 + 간단 문서)” 1개
B) 한글 깨짐(인코딩/charset/정적파일) “상시 점검 체크리스트” + 필요한 최소 수정(발견 시) 1개
C) 이후 티켓(ATT-1~5)에 그대로 복붙할 수 있는 “공통 Done 기준”을 코드/문서로 남긴다.

------------------------------------------------------------
1) Discovery: Attachment가 어디에 저장/연결되는지 확인(필수)
------------------------------------------------------------
- 프로젝트 내 첨부 저장 방식 점검:
  - Evidence 모델의 attachments(파일)인지,
  - 공통 Attachment/File 모델인지,
  - object_type/object_id로 연결되는지,
  - 또는 각 도메인 객체(Progress/Cost/Report/Timesheet)가 file field를 직접 갖는지
- 아래 화면에서 첨부가 이미 노출되는 위치를 찾고 목록화:
  - 진행률 상세/목록
  - 원가 상세/목록
  - 보고서 상세/목록
  - 출역부 상세/목록
  - HQ 상세(승인/검토 페이지)
  - CEO 승인 상세(/app/ceo/approvals/<id>/)
- “임시저장 파일 유지 후 제출” 패턴이 탭마다 동일하게 동작하는지 확인:
  - 임시저장(DRAFT)에서 업로드한 파일이 제출(SUBMITTED) 시에도 유지되는가?
  - 수정 시 파일이 중복 생성되는가(버그 가능)?
  - 제출 후 수정 불가/잠금 정책과 충돌 없는가?

Discovery 결과는 아래 포맷으로 짧게 기록(코드 주석 또는 docs/ATTACHMENTS.md):
- Source 모델/연결 방식
- 각 화면의 현재 템플릿/뷰 파일 경로
- 첨부 렌더링이 들어가는 블록명/함수명
- 임시저장→제출 시 파일 유지 여부(OK/이슈)

------------------------------------------------------------
2) Attachment 표준 정책 확정(필수)
------------------------------------------------------------
다음 표준을 “프로젝트 공통 규칙”으로 고정한다(문서 + 코드 주석):

2.1 상세 페이지(DETAIL) 표준
- 이미지(jpg/png/webp/gif)는 “인라인 미리보기”로 바로 보이게 한다.
- 비이미지(pdf/doc/xlsx/zip 등)는 “파일 리스트”로 표시 + 링크 제공.
- 링크 동작:
  - 이미지: 인라인(기본), 필요 시 “원본 보기(새 탭)” 보조 링크 제공
  - 비이미지: 새 탭 열기(target=_blank) 기본(다운로드/보기 선택은 브라우저)
- 다중 업로드: 상세에서 항상 “목록 + 썸네일(이미지)” 형태로 표시

2.2 목록 페이지(LIST) 표준
- 각 row에 “첨부됨” 아이콘 + 개수만 표시(과도한 썸네일 금지)
  - 예: 📎 2 또는 🖼 1 (이미지 포함 시 우선 🖼)
- 아이콘은 텍스트/이모지 또는 기존 아이콘 라이브러리 중 1개로 통일

2.3 권한/보안 표준
- 사용자는 본인 권한 범위 내 첨부만 볼 수 있다(RBAC 준수)
- S3 프리사인 URL 사용 중이면 기존 정책 유지(만료/권한 변경 금지)
- “마감/제출 잠금”은 ‘업로드 금지/수정 금지’에만 영향:
  - 이미 존재하는 첨부 “조회”는 가능(권한 내)

2.4 임시저장 파일 유지 표준
- DRAFT에 업로드한 파일은 SUBMITTED로 상태 전환 시 유지되어야 한다.
- 수정 저장 시 “중복 첨부 생성”은 금지:
  - 동일 파일이 중복으로 쌓이지 않게 로직 점검(업로드 처리에서 append 방식 주의)
- 제출 후에는 첨부 추가/삭제 불가(정책이 그렇다면 반드시 UI에서도 차단)

2.5 모바일 표준
- 모바일에서도 다중 업로드가 동일하게 동작해야 한다:
  - 선택(여러 파일) → 업로드 → 목록 표시 → 제출 후 잠금
- 인라인 미리보기는 모바일 폭에 맞춰 반응형으로(가로 스크롤 금지)

------------------------------------------------------------
3) 한글 깨짐(UTF-8) 상시 점검 + 최소 수정(필수)
------------------------------------------------------------
목표
- FIELD/HQ/CEO 화면에서 한글 라벨/버튼/문구가 깨지는 재발을 막는다.
- 원인 스캔 후, 발견되는 경우 “최소 수정”으로 정리한다(대규모 리팩터 금지).

3.1 점검 항목(필수)
A) base 템플릿(meta charset)
- 모든 HTML은 최상위 base 템플릿에 <meta charset="utf-8"> 가 있어야 한다.
- 중복 선언/누락이 있으면 base 1곳으로 통일.

B) Django 응답 charset
- settings 또는 middleware에서 Content-Type charset이 UTF-8로 나가는지 확인.
- 템플릿 렌더에서 깨지는 경우, response headers를 점검.

C) 정적파일 인코딩
- 한글 문자열이 들어간 JS/CSS 파일이 UTF-8로 저장되어 있는지 확인.
- 깨짐이 재현되는 페이지에서 로드되는 템플릿/JS/CSS를 우선 점검.

D) 폰트/렌더 문제
- 폰트 로딩 실패로 한글이 네모(□)로 나오는지 확인(인코딩과 다른 문제).
- 필요 시 기본 폰트 스택에 한국어 폰트(예: "Noto Sans KR", "Malgun Gothic")를 추가하되,
  기존 디자인을 깨지 않도록 최소 변경.

3.2 “상시 회귀 체크”를 문서/코드로 고정(필수)
- docs/QUALITY_CHECKLIST.md 또는 docs/ATTACHMENTS.md에 아래 공통 체크를 추가:
  - [ ] FIELD(/app/field/) 한글 라벨/버튼/상태 뱃지 정상
  - [ ] HQ(/app/hq/) 한글 라벨/버튼/상태 뱃지 정상
  - [ ] CEO(/app/ceo/, /app/ceo/approvals/<id>/) 한글 라벨/버튼/상태 뱃지 정상
  - [ ] base 템플릿 meta charset UTF-8 확인
  - [ ] 한글 포함 JS/CSS 파일 UTF-8 저장 확인
- 이후 ATT-1~5의 PR 템플릿 또는 Issue Done 기준에 그대로 복붙할 수 있게 한다.

------------------------------------------------------------
4) ATT-1~ATT-5에 전달할 “공통 Done 기준” (필수)
------------------------------------------------------------
아래 문구를 docs에 저장하고, ATT-1~5 프롬프트에도 그대로 붙이도록 한다:

[공통 Done 기준]
- 첨부(Attachment) 표준: 상세=인라인 미리보기+리스트, 목록=아이콘+개수, 링크 정책 통일
- 임시저장 파일 유지 후 제출: 파일 중복 생성 없음, 제출 후 업로드/삭제 불가(정책 준수)
- 모바일에서도 다중 업로드/표시 동일 동작
- 한글 깨짐 0: FIELD/HQ/CEO 주요 페이지에서 한글 라벨/버튼/상태 뱃지 정상
- N+1 쿼리 없음, 성능 저하 없음

------------------------------------------------------------
5) 이 티켓의 완료 기준(Acceptance)
------------------------------------------------------------
- (문서) Attachment 표준(상세/목록/권한/임시저장/모바일/링크) 규칙이 docs로 남아 있다.
- (문서) 한글 깨짐 방지 체크리스트가 docs로 남아 있고, 재현 페이지에서 점검 결과가 기록되어 있다.
- (코드) base 템플릿/응답 헤더/정적파일 인코딩 중 명백한 문제 1~N개가 발견되면 “최소 수정”으로 해결한다.
- (검증) FIELD/HQ/CEO 각 1개 핵심 페이지에서 한글이 깨지지 않는다.
- (후속) ATT-1~ATT-5에 사용할 공통 Done 기준이 준비되어 있다.
