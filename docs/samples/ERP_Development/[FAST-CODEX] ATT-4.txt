[FAST-CODEX] ATT-4: 원가/보고서/출역부 + HQ 상세/목록 첨부 UX 전면 통일 (공통 컴포넌트 적용) + 임시저장/반려 패턴 점검/수정 + 한글 회귀 테스트

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 기존 설계/모델/URL 유지, 재설명 불필요
- DB 스키마 변경 금지
- ATT-1(REV) 공통 컴포넌트 사용(필수)
  - templates/components/attachments_panel.html  (상세: 인라인 미리보기 + 리스트 + can_edit에 따른 업로드/삭제 UI)
  - templates/components/attachment_badge.html   (목록: 아이콘 + 개수)
- 첨부 편집 정책(필수, 전 탭 공통)
  - DRAFT(임시저장), REJECTED(반려): 제출 전까지 첨부 추가/교체/삭제 가능
  - SUBMITTED(제출), APPROVED(승인): 첨부 변경 불가(조회만)
  - 마감(CLOSE-2/CLOSE-4) 잠금이면 상태와 무관하게 첨부 변경 불가(조회만)
- 링크 정책(필수, 전 화면 통일)
  - 이미지: 상세에서 인라인 미리보기 + “원본 보기(새 탭)”
  - 비이미지: 새 탭 열기(target=_blank) 기본
  - 목록에서는 썸네일 금지, 아이콘+개수만

목표
1) 원가/보고서/출역부 탭의 상세/목록에서 첨부 표시가 공통 컴포넌트로 완전히 통일
2) HQ 상세(승인/검토/상세)에서도 동일 첨부 UX 적용(새탭 정책 포함)
3) 임시저장 파일 유지 → 제출 → 반려 → 수정 → 재제출 플로우가 탭별로 동일하게 작동하도록 점검하고, 차이가 있으면 수정
4) 한글(라벨/버튼/에러/핵심 메시지) 회귀 테스트 통과(깨짐 0)

------------------------------------------------------------
1) Discovery (필수, 먼저 실행)
------------------------------------------------------------
아래 대상 화면들의 URL/뷰/템플릿 경로를 찾아 목록화하고,
첨부 연결 방식 + 업로드 엔드포인트 + 상태 필드를 확인한다.

대상(필수)
- FIELD 원가 탭: 목록/최근입력 + 상세(수정/조회) 화면
- FIELD 보고서 탭: 업로드 목록 + 상세(수정/조회) 화면
- FIELD 출역부 탭: 목록 + 상세(입력/수정/조회) 화면
- HQ 상세:
  - HQ Inbox/상세에서 특정 항목(원가/보고서/출역/진행률/변경요청 등)을 보는 화면
  - HQ 승인/반려 화면이 별도면 그 화면도 포함

Discovery에서 다음을 반드시 기록(docs/ATTACHMENTS.md에 간단히):
- 템플릿 파일 경로
- view 함수/클래스 경로
- 상태 필드명/상태 값 매핑(DRAFT/SUBMITTED/APPROVED/REJECTED)
- attachments를 가져오는 방법(직접 관계 / Evidence / object_type/object_id)
- 업로드/삭제/교체 처리 URL(이미 존재하는지)

------------------------------------------------------------
2) 각 탭/화면에 공통 컴포넌트 적용 (핵심)
------------------------------------------------------------
공통 원칙
- 상세 화면: attachments_panel include (can_edit/upload_url/delete_url 전달)
- 목록 화면: attachment_badge include (N+1 방지)

2.1 상세 화면 공통 적용(원가/보고서/출역 + HQ 상세)
각 상세 템플릿에 아래 include를 삽입:
{% include "components/attachments_panel.html" with attachments=attachments can_edit=can_edit upload_url=upload_url delete_url=delete_url object_label=object_label help_text=help_text %}

View에서 컨텍스트 준비(필수)
- attachments:
  - 해당 객체(원가/보고서/출역) 기준으로 연결된 attachments list/queryset
  - Evidence 구조면 object_type/object_id로 Evidence를 찾아 attachments 추출
- can_edit:
  - 공통 정책 함수(ATT-1에서 만든 util)로 계산:
    - is_closed_locked = CLOSE-2/CLOSE-4 규칙으로 잠금 판정
    - status = 해당 객체 상태
    - can_edit = policy(status, is_closed_locked)
- upload_url:
  - “첨부 업로드/교체”를 처리하는 기존 URL을 연결(가능하면 해당 상세 POST 또는 전용 업로드 URL)
- delete_url(선택):
  - 삭제 엔드포인트가 있으면 연결
  - 없다면 None → 컴포넌트가 삭제 버튼을 숨기도록
- object_label:
  - "원가" / "보고서" / "출역부" / "HQ 상세" (화면에 표시될 한글 라벨)
- help_text:
  - can_edit=True: "임시저장/반려 상태에서는 제출 전까지 첨부를 수정할 수 있습니다."
  - can_edit=False: "제출/승인/마감 상태에서는 첨부를 수정할 수 없습니다."

주의(중요)
- 승인/반려 버튼이 있는 HQ 상세/CEO 상세 등에서는
  attachments_panel이 기존 <form>을 깨지 않도록 중첩 form 금지
- 첨부 UI는 조회 중심이며, can_edit일 때만 업로드/삭제 UI가 노출

2.2 목록 화면 공통 적용(원가/보고서/출역 목록 + HQ 목록/Inbox 목록)
목록의 각 row/card에 아래 include:
{% include "components/attachment_badge.html" with attachments=row_attachments %}

N+1 방지(필수)
- 목록의 모든 row에 대해 attachments를 개별 조회하면 안 됨
- 탭별로 아래 중 하나를 적용:
  A) prefetch_related로 attachments/evidence->attachments를 미리 로드
  B) object ids를 모아 한번에 attachments를 조회해 dict로 매핑(attachments_map)
- 템플릿에는 row_attachments가 이미 준비된 형태로 전달

아이콘 규칙
- 이미지 포함이면 🖼 우선, 아니면 📎
- 개수 표시

------------------------------------------------------------
3) “임시저장 파일 유지 후 제출” 패턴 탭별 점검 및 수정(필수)
------------------------------------------------------------
핵심 요구
- DRAFT에서 업로드한 파일은 SUBMITTED 전환 시 유지되어야 함
- SUBMITTED에서는 첨부 변경 불가(조회만)
- REJECTED(반려)되면 첨부 변경 가능(다시 제출 전까지)

탭별로 반드시 확인/수정할 것
A) 원가
- DRAFT 저장 후 첨부가 상세/목록에 보이는지
- 제출하면 첨부 변경 UI가 사라지는지(서버도 거부)
- 반려되면 첨부 변경 UI가 다시 보이는지
- 수정 저장 시 “중복 첨부가 계속 쌓이는 문제”가 없도록 확인
  - 기존에 중복 버그가 있었다면 업로드 처리에서 append만 하는지 점검
  - 같은 파일을 중복 추가하지 않도록 최소 수정(스키마 변경 금지)

B) 보고서
- 동일 날짜 여러 건 보고서 구조(이미 구현된 전제)에서
  각 보고서별 첨부가 정확히 붙는지
- 수정 저장 시 기존 첨부 유지/교체가 정상인지
- 제출/반려 흐름 동일

C) 출역부
- DRAFT에서 첨부가 가능한 구조라면 동일 적용
- 출역부에 첨부가 없다면(정책상 미사용)도:
  - 목록/상세 렌더가 오류 없이 동작해야 함(attachments 빈 리스트)

D) HQ 상세
- HQ가 보는 상세 화면에서도 첨부가 동일 표시
- HQ는 can_edit 정책에 따라:
  - HQ가 첨부를 수정하는 것이 정책상 허용되지 않으면 can_edit=False로 고정(조회만)
  - 허용한다면 동일 정책 적용(DRAFT/REJECTED에서만)
- 마감 잠금이면 무조건 can_edit=False

중요: 서버 가드(필수)
- can_edit=False 상태에서 업로드/삭제 요청은 반드시 거부(HTTP 403 또는 form error)
- 프론트에서만 숨기는 것은 불충분

------------------------------------------------------------
4) 링크/새탭 정책 전면 통일(필수)
------------------------------------------------------------
아래 정책이 원가/보고서/출역/HQ 상세·목록에서 동일해야 한다.
- 상세에서 이미지: 인라인 + “원본 보기(새 탭)”
- 상세에서 비이미지: 파일명 링크 클릭 시 새 탭(target=_blank)
- 목록에서는 아이콘+개수만(링크는 상세로 들어가서 확인)
- 기존 화면에서 “다운로드 링크 클릭 시 별도 탭” 정책이 있었다면 유지하되,
  공통 컴포넌트 정책에 맞춰 일관화

------------------------------------------------------------
5) 한글 체크(필수, 회귀 테스트)
------------------------------------------------------------
각 탭/화면에서 아래를 반드시 확인하고 깨짐 발견 시 최소 수정한다.
- 라벨/버튼(임시저장/제출/승인/반려/수정/삭제/업로드)
- 에러 메시지(범위/필수/권한/잠금)
- 핵심 메시지:
  - “제출 후 수정 불가”
  - “마감 상태로 인해 …”
  - “소급 입력은 HQ 요청 …” (있다면)
- base 템플릿 meta charset UTF-8
- 한글 포함 JS/CSS 파일 UTF-8 저장 확인

------------------------------------------------------------
6) 완료 기준(Acceptance)
------------------------------------------------------------
- 원가/보고서/출역/HQ의 상세 화면에서 첨부 UX가 attachments_panel로 통일되고,
  이미지 인라인 미리보기 + 파일 리스트 + 새탭 정책이 일관되게 동작한다.
- 원가/보고서/출역/HQ의 목록 화면에서 첨부 배지(🖼/📎 + 개수)가 통일되어 표시된다(N+1 없음).
- 임시저장(DRAFT)에서 첨부 수정 가능, 제출(SUBMITTED)/승인(APPROVED)에서 수정 불가,
  반려(REJECTED)에서 다시 수정 가능 흐름이 탭별로 동일하게 동작한다.
- “임시저장 파일 유지 후 제출” 패턴에서 중복 첨부가 쌓이는 문제가 없다(있으면 최소 수정으로 해결).
- 각 탭 라벨/버튼/에러/핵심 메시지 한글이 깨지지 않는다(깨짐 0).

실행 지시
1) Discovery로 템플릿/뷰/상태/첨부 연결/업로드 URL을 전부 파악하라.
2) 상세에 attachments_panel include + 컨텍스트(attachments/can_edit/upload_url/delete_url)를 연결하라.
3) 목록에 attachment_badge include + N+1 없는 attachments 매핑을 구현하라.
4) DRAFT→SUBMITTED→REJECTED 흐름에서 첨부 변경 정책이 동일하게 동작하도록 점검/수정하라.
5) 링크 정책을 전면 통일하라.
6) 한글 회귀 테스트를 통과하도록 최소 수정하라.
