[FAST-CODEX] ATT-4B (STOP-RULE VERSION): 원가/보고서/출역/HQ ‘목록 화면’ 첨부 배지(🖼/📎+개수) 통일 적용 + 최소 성능 보장

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

STOP RULE(반드시 지킬 것)
- Discovery는 최대 6개 파일만 확인하고 종료한다.
- 수정 파일은 최대 6개까지만 변경한다.
- 서버 실행/테스트는 최대 1회만 한다.
- 상세 화면(attachments_panel) 수정 금지(ATT-4A 범위 밖).
- 큰 리팩터/새 모델/새 스키마/새 승인정책/새 UI 제안 금지.
- N+1 완전 최적화는 “가능하면 적용” 수준까지만(과도한 설계 금지).
- 이 티켓 목표 달성 후 즉시 종료한다(추가 개선 제안은 TODO로만 기록).

범위(목록 화면만)
- FIELD 원가 목록(최근입력 포함): 1곳
- FIELD 보고서 업로드 목록: 1곳
- FIELD 출역부 목록: 1곳
- HQ Inbox(승인 대기 목록 또는 업무 목록): 1곳
※ 목록 화면이 여러 개라면 “실제 사용되는 대표 목록 1개씩”만 선택.

목표
1) 각 목록 row/card에 공통 배지 컴포넌트 적용:
   - templates/components/attachment_badge.html
2) 배지 규칙:
   - 첨부 1개 이상일 때만 표시
   - 이미지 포함 시 🖼 우선, 아니면 📎
   - 개수 표시(🖼 2 / 📎 1)
3) 성능:
   - 목록 렌더가 느려지지 않게 “최소한의” 사전 로딩 적용
   - N+1이 명백하면 prefetch 또는 1회 조회+dict 매핑 중 “가장 쉬운 것”만 적용

구현 지시
1) Discovery(최대 6개 파일)
   - 각 목록 템플릿 파일/뷰 파일 위치 확인
   - row에서 “원본 객체 id” 접근 가능 여부 확인
   - attachments가 직접 관계인지(Evidence/Attachment 관계) 확인

2) 템플릿 변경(각 목록 row에 배지 삽입)
   - row 단위로 attachments가 준비되어 있으면:
     {% include "components/attachment_badge.html" with attachments=row_attachments %}
   - 준비가 안 되어 있으면:
     - view에서 attachments_map을 만들어 템플릿에 전달 후:
       {% include "components/attachment_badge.html" with attachments=attachments_map[row.id] %}

3) attachments_map(최소 성능 보장 방식 택1)
   A) 직접 관계(related_name)면:
      - queryset에 prefetch_related(...) 추가
      - 템플릿에서 row.attachments.all 사용(가능한 구조면)
   B) Evidence(object_type/object_id) 방식이면:
      - 목록에 포함된 object_id들을 한 번에 수집
      - Evidence를 1회 조회(filter object_id__in=..., object_type=...)
      - Evidence별 attachments를 prefetch
      - object_id → attachments list로 dict 구성

4) 한글 회귀 체크(필수, 최소)
   - 목록 상단/버튼/컬럼명 한글이 깨지지 않는지 확인
   - 깨짐 발견 시 base charset/해당 템플릿 UTF-8 저장만 최소 수정

Acceptance
- 4개 목록 화면(원가/보고서/출역/HQ Inbox) row에 배지(🖼/📎+개수)가 표시된다.
- 첨부가 없으면 배지가 나타나지 않는다.
- 목록 성능이 체감상 악화되지 않는다(명백한 N+1이면 최소 해결).
- 한글 라벨/버튼이 깨지지 않는다.
- 이 티켓에서 멈춘다(추가 개선 금지).
