[FAST-CODEX] ATT-4C (STOP-RULE VERSION): “임시저장/반려 상태에서 첨부 수정 시 중복 누적” 버그 제거 (보고서/원가/출역 중 실제 발생 탭 1곳만) + 재제출 플로우 안정화

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

STOP RULE(반드시 지킬 것)
- Discovery는 최대 5개 파일만 확인하고 종료한다.
- 수정 파일은 최대 5개까지만 변경한다.
- 서버 실행/테스트는 최대 1회만 한다.
- UI 리디자인/공통 컴포넌트 수정 금지(ATT-1~4A/B 범위 밖).
- 스키마 변경/대규모 리팩터 금지.
- “버그 원인 제거”만 하고 즉시 종료한다.

범위(문제 발생 1곳만 선택)
- 우선순위: 보고서 탭(업로드 목록에서 수정 저장 후 ‘기존 제목+수정 제목’이 같이 쌓이는 현상) → 가장 유력
- 만약 보고서가 아니라 원가/출역에서 재현된다면, 재현되는 탭 1곳만 대상으로 한다.

목표
1) 임시저장(DRAFT) 후 상세에서 수정 저장할 때
   - 기존 레코드가 “새 레코드로 추가”되지 않고
   - 같은 레코드가 업데이트되며 목록에 1건만 남도록 한다.
2) 반려(REJECTED) 후 수정 저장에서도 동일(중복 생성 금지)
3) 첨부 파일 변경(추가/삭제/교체)이 동작하되,
   - 기존 첨부가 매번 append되어 중복으로 쌓이지 않도록 한다(가능한 범위에서 최소 수정)
4) 제출(SUBMITTED)/승인(APPROVED) 상태에서는 변경이 막히는 기존 정책 유지

Discovery(필수, 최대 5개 파일)
1) 해당 탭의 “작성/수정 저장” 뷰를 찾는다:
   - create/update가 분리인지, 동일 view에서 처리하는지
2) 목록이 쌓이는 원인 확인:
   - POST 처리에서 항상 create() 하는지
   - update 시에도 pk를 못 잡고 새 인스턴스를 만드는지
   - 폼 action이 잘못된 URL로 create 엔드포인트를 치는지
3) 첨부 중복 원인 확인:
   - 업로드 처리에서 attachments.add(...)만 반복하는지
   - “기존 첨부를 유지/교체” 로직이 없는지

수정 지시(최소 변경)
A) “수정 저장은 update로” 고정
- edit URL에서 반드시 해당 객체 pk를 받아 update해야 한다.
- 폼 action이 create URL을 가리키면 edit URL로 수정
- view는 다음 중 하나로 정리(스키마 변경 없이):
  - get_object_or_404로 기존 객체를 가져와 form = Form(request.POST, instance=obj)
  - 저장 시 obj = form.save()로 update
- 상태 가드:
  - status in (SUBMITTED, APPROVED) 또는 is_closed_locked면 수정 저장 거부(403 또는 메시지)

B) “첨부 중복 누적” 최소 제거
- can_edit=True(DRAFT/REJECTED, not closed)일 때만 업로드 처리
- 업로드가 “추가”인지 “교체”인지 정책을 단순화:
  - 기본은 “추가” 허용
  - 단, 동일 파일(같은 name/size 등)이 이미 있으면 다시 add하지 않도록 최소 필터(가능하면 file id 기준)
- 만약 기존 로직이 매번 “새 Evidence 생성”을 해서 중복이 생긴다면:
  - 해당 객체에 연결된 Evidence를 재사용하도록(있으면 가져오고 없으면 생성) 최소 수정
  - 동일 object_type/object_id에 Evidence가 여러 개 생기지 않게 방지

C) 목록 중복(제목이 2개 보임) 해결
- “수정 저장” 후 목록 쿼리가 중복 레코드를 포함하는지 확인:
  - 동일 날짜/동일 작성자/동일 참조키로 중복 생성된 레코드가 있는지
- 해결은 “중복 데이터 삭제”가 아니라 “앞으로 중복 생성 방지”가 우선
- 데모에서 이미 생성된 중복 데이터는 관리 화면에서 정리 가능(이번 티켓 범위 밖)

검증 시나리오(필수, 1회만)
1) DRAFT로 1건 생성 + 첨부 1개 업로드 → 목록 1건
2) 상세로 들어가 제목/내용 수정 + 첨부 1개 추가 → 저장 → 목록이 여전히 1건(제목이 교체됨)
3) 제출(SUBMITTED) 후 수정 시도 → 차단
4) (가능하면) 반려(REJECTED)로 바꾼 뒤 수정 저장 → 목록 1건 유지 + 첨부 변경 가능

한글 회귀 체크(필수, 최소)
- 해당 탭의 버튼/에러 메시지 한글이 깨지지 않는지 확인
- 깨짐 발견 시 base charset/해당 템플릿 UTF-8 저장만 최소 수정

Acceptance
- 수정 저장 시 기존 항목이 “대체(update)”되고 목록에 중복으로 쌓이지 않는다.
- 첨부 변경 시 중복 첨부가 무한히 누적되지 않는다(가능한 최소 범위에서 방지).
- 제출/승인/마감 정책은 그대로 유지된다.
- 한글 깨짐이 재현되지 않는다.
- STOP RULE 준수: 파일/테스트 제한 지키고 여기서 종료한다.
