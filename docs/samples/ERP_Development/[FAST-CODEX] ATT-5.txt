[FAST-CODEX] ATT-5: 모바일 멀티업로드 E2E 점검/보완 + CEO “승인 완료 목록” → 객체 상세 이동 + 첨부 인라인 확인 + 한글/폰트 안정화

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 기존 설계/모델/URL 유지
- DB 스키마 변경 금지
- ATT-1(REV)~ATT-4 완료 상태를 전제로 한다:
  - 공통 첨부 컴포넌트(attachments_panel, attachment_badge) 적용 완료
  - 첨부 편집 정책:
    - DRAFT/REJECTED: 제출 전 첨부 변경 가능
    - SUBMITTED/APPROVED: 첨부 변경 불가(조회만)
    - 마감 잠금: 무조건 변경 불가(조회만)
- 이번 티켓은 “모바일 멀티업로드 실제 동작”을 끝까지 점검하고, 부족하면 최소 수정으로 보완한다.
- CEO 대시보드에 “승인 완료 목록” 진입 동선을 추가하되,
  클릭 시 Approval 상세가 아니라 “원본 객체 상세(진행률/보고서/원가/출역)”로 이동하게 한다.

목표
1) 모바일에서 다중 업로드가 실제로 동작:
   - 선택(여러 파일) → 업로드 → 표시(미리보기/리스트) → 삭제/교체(가능 상태에서) → 제출 후 잠금에서도 유지
2) CEO 대시보드에서 “승인 완료 목록”을 제공:
   - 목록에서 각 항목 클릭 시 해당 객체 상세로 이동
3) 객체 상세에서 첨부 인라인 미리보기 즉시 확인(이미 ATT-2~4로 구현됨을 재사용)
4) 한글/폰트/인코딩이 모바일에서 안정(줄바꿈/깨짐/라벨 이상 없음)

------------------------------------------------------------
1) Discovery (필수)
------------------------------------------------------------
1.1 모바일 전용 페이지 범위 확인
- “모바일 전용 페이지”가 별도 템플릿/URL인지(예: /m/app/field/ 또는 모바일 분기 템플릿) 확인
- FIELD 모바일에서 멀티업로드가 필요한 화면:
  - 진행률 입력/상세
  - 보고서 입력/상세
  - 원가 입력/상세
  - 출역부 입력/상세 (첨부가 있는 경우)
- 각 화면에서 업로드 input이 단일/다중인지 확인:
  - <input type="file" multiple> 여부
  - 폼 enctype="multipart/form-data" 여부
  - 서버 측에서 files.getlist(...) 처리 여부(Django)

1.2 CEO 승인 완료 목록 데이터 소스 확인
- CEO 대시보드(/app/ceo/ 또는 /ceo/dashboard/)에서 승인 관련 데이터가 어디서 오는지 확인
  - ApprovalRequest(또는 유사) 모델의 status=APPROVED 필터 가능 여부
  - 승인 완료 시간(approved_at) 또는 updated_at 확인
  - 승인 대상(target object) 식별( object_type/object_id or content_type/object_id )

------------------------------------------------------------
2) 모바일 멀티업로드 실제 동작 점검 + 최소 수정
------------------------------------------------------------
2.1 테스트 시나리오(필수, 각 탭 공통)
각 탭(진행률/보고서/원가/출역부)에 대해 모바일 브라우저에서 아래를 수행:
A) DRAFT(임시저장)
- 2~5개의 파일을 선택(이미지 2개 + 비이미지 1개 이상 가능하면 포함)
- 저장(임시저장)
- 상세로 들어가 첨부가 모두 표시되는지(인라인/리스트)
- 목록 배지(🖼/📎 + 개수)가 맞는지

B) DRAFT에서 첨부 변경
- 1개 파일 추가 업로드(추가)
- 1개 삭제(삭제 기능이 제공되는 경우)
- 1개 교체(교체가 “삭제+추가” 흐름이면 그 방식으로)
- 중복 첨부가 쌓이지 않는지 확인

C) 제출(SUBMITTED)
- 제출 후 첨부 변경 UI가 사라지는지(조회만)
- 첨부는 그대로 유지되며 인라인 미리보기 가능해야 함
- 서버에서 업로드/삭제 요청이 거부되는지(보안)

D) 반려(REJECTED)
- 반려 상태에서 첨부 변경 UI가 다시 보이는지
- 수정 후 재제출 시 잠금 재적용되는지

E) 마감 잠금(CLOSED)
- 마감 상태에서 첨부 변경 UI가 절대 보이지 않는지(조회만)

2.2 발견 가능한 대표 이슈에 대한 최소 수정 가이드(발견 시 적용)
- 멀티 선택이 안 됨:
  - input에 multiple 속성 누락 → 추가
- 서버에서 파일 1개만 저장됨:
  - request.FILES['file'] 단일 처리 → request.FILES.getlist('files') 등으로 멀티 처리(기존 설계에 맞춰 최소 수정)
- 모바일에서 업로드 후 표시가 늦거나 깨짐:
  - 저장 후 리다이렉트/리렌더 타이밍 점검
  - attachments_panel이 빈 attachments를 렌더하지 않도록 조건 처리
- 삭제/교체 버튼이 모바일에서 눌리기 어려움:
  - 버튼 크기/간격만 최소 조정(디자인 대개편 금지)
- iOS에서 사진 업로드 후 회전/표시 문제:
  - 가능한 범위에서 CSS object-fit 적용 또는 브라우저 기본 처리 유지(과도한 이미지 처리 금지)

주의
- DB 스키마 변경 금지
- 대규모 업로드 로직 리팩터 금지
- “정책(can_edit)”은 바꾸지 말고, UI/폼/서버 파일 수집만 최소 수정

------------------------------------------------------------
3) CEO “승인 완료 목록” → 객체 상세 이동
------------------------------------------------------------
3.1 CEO 대시보드에 섹션 추가
- CEO 대시보드 상단 또는 KPI 카드 하단에 “최근 승인 완료” 섹션 추가
  - 기본 10건
  - 정렬: approved_at desc (없으면 updated_at desc)
  - 표시 컬럼:
    - 승인 대상 라벨(진행률/보고서/원가/출역부)
    - 프로젝트명(가능하면)
    - 일자(대상 객체 date 또는 created_at)
    - 승인일시
    - (선택) 첨부 배지(있으면 🖼/📎 + 개수; 성능 문제 없으면)

3.2 “객체 상세 URL” 생성 규칙(핵심)
- 승인 완료 항목 클릭 시:
  - /app/ceo/approvals/<id>/ 로 가지 말고,
  - 해당 대상 객체의 “상세 페이지”로 이동해야 한다.
- 타입별 상세 URL 매핑을 서버에서 만든다(템플릿에서 하드코딩 금지):
  - 예: 진행률 → /app/field/progress/<id>/detail/ 또는 /app/ceo/progress/<id>/ (기존 실제 URL에 맞춤)
  - 보고서 → /app/field/reports/<id>/ or /app/ceo/reports/<id>/
  - 원가 → /app/field/cost/<id>/...
  - 출역부 → /app/field/timesheet/<id>/...
- “CEO가 객체 상세를 볼 권한이 없다”면(정책상):
  - CEO 전용 상세 뷰를 만들지 말고, 기존 CEO 권한으로 접근 가능한 상세 URL을 사용
  - 필요 시 CEO 전용 read-only detail 뷰를 추가(단, 최소 구현)

3.3 구현 방식(권장)
- ApprovalRequest 모델에 method 추가(스키마 변경 없음):
  - def get_target_detail_url(self) -> str
  또는 util 함수:
  - build_target_detail_url(approval)
- CEO 대시보드 view에서 approvals를 조회하고, 각 항목에 detail_url을 붙여 템플릿에 전달
- 템플릿은 detail_url로 링크만 건다

3.4 첨부 인라인 확인
- 사용자가 객체 상세로 이동하면, ATT-2~4에서 적용된 attachments_panel로 첨부가 인라인 표시되어야 한다.
- 만약 CEO가 보는 상세가 별도라 attachments_panel이 없으면:
  - 최소로 해당 CEO 상세 템플릿에도 attachments_panel include를 추가(조회만, can_edit=False)

------------------------------------------------------------
4) 한글/폰트/인코딩 모바일 안정화(필수)
------------------------------------------------------------
4.1 모바일 레이아웃 한글 점검
- FIELD 모바일 페이지(진행률/보고서/원가/출역)에서:
  - 한글 줄바꿈(어색한 중간 끊김), 깨짐(????), 버튼 라벨 잘림 여부 점검
- CEO 모바일에서도:
  - “최근 승인 완료” 섹션 라벨/버튼 깨짐 여부 확인

4.2 iOS Safari / Android Chrome 점검(가능한 범위)
- 실제 기기 테스트가 불가하면:
  - 최소한 반응형 뷰포트에서 CSS/font 설정이 안전한지 점검
- 폰트/인코딩 최소 안정화:
  - base 템플릿 meta charset UTF-8 확인(중복/누락 수정)
  - 기본 폰트 스택에 한국어 폰트 1개만 최소 추가:
    - "Noto Sans KR", "Malgun Gothic", system-ui 등
  - 템플릿/JS/CSS UTF-8 저장 확인

------------------------------------------------------------
5) 완료 기준(Acceptance)
------------------------------------------------------------
- 모바일에서 진행률/보고서/원가/출역부의 다중 업로드가 실제로 동작:
  - 선택/업로드/표시/삭제(가능 시)/유지/제출 후 잠금/반려 후 수정 가능 흐름이 정상
- CEO 대시보드에 “최근 승인 완료” 목록이 추가되고,
  각 항목 클릭 시 Approval 상세가 아니라 “원본 객체 상세”로 이동한다.
- 객체 상세에서 첨부가 인라인으로 즉시 확인된다.
- 모바일/PC/CEO 동선에서 한글 깨짐이 재현되지 않는다.
- iOS/Android 환경에서 폰트/인코딩 문제를 최소화하도록 base/정적파일 UTF-8 및 폰트 스택이 안정화되어 있다.

실행 지시
1) 모바일 전용 페이지/업로드 처리 구조를 Discovery로 파악하라.
2) 각 탭에서 멀티업로드 E2E 시나리오(A~E)를 수행하고, 발견되는 문제만 최소 수정하라.
3) CEO 대시보드에 “최근 승인 완료” 섹션을 추가하고, 타입별 detail_url을 서버에서 생성해 객체 상세로 이동하게 하라.
4) 객체 상세에 첨부 인라인 표시가 확실히 보이도록(필요 시 can_edit=False로 패널 include) 보완하라.
5) 모바일 한글/폰트/인코딩 회귀 테스트를 통과하도록 최소 수정하라.
