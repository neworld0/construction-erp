[FAST-CODEX] D3E-3: DEMO-3SITES-E2E (운영 데이터 생성 + 승인흐름 혼합) 구현

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

STOP RULE
- DB 스키마 변경 금지
- 수정 파일 최대 8개
- 서버 실행/테스트 1회
- 성능 최적화/N+1 개선 금지(데모 생성만)

전제
- D3E-2까지 완료되어 프로젝트/마스터가 존재
- D3E-1의 STATUS_MAP/TYPE_MAP을 사용

기간
- 운영 데이터 생성 범위: 2026-02-01 ~ 2026-02-28
- 프로젝트별 8~12일치(주 2~3회 느낌)

목표(프로젝트별 생성)
1) 진행률(Progress)
- DRAFT → SUBMITTED → APPROVED 혼합
- 일부는 REJECTED 후 재제출 케이스 포함
- 첨부:
  - 사진 1~3장 더미 이미지 파일 생성 후 연결(가능하면 jpg/png)
  - (R1 케이스용) 1건은 첨부 없이 SUBMITTED만

2) 보고서(Report)
- 같은 날짜에 2건 이상 생성되는 날 포함
- DRAFT/REJECTED 상태에서 첨부 교체 케이스 1회 포함(R3)
- 목록 중복 생성이 없도록 “수정은 update” 패턴 준수(이미 ATT-4C가 적용된 상태 가정)

3) 원가(CostActual)
- 같은 날짜 여러 건 생성
- 일부는 증빙 첨부 포함
- (R2 케이스용) 1건은 첨부 없이 SUBMITTED

4) 출역부(Timesheet)
- 6~10일치 생성
- 일부는 승인 대기 상태로 월말까지 남겨둠(R4)
- 승인/반려 혼합

5) 재고(INV)
- HQ 입고 5~10건
- Transfer 본사↔현장 3~6건
- “자재투입”:
  - IssueToWork 모델이 존재하면 3~6건 생성하고 CBS/원가 자동 집계 연결
  - IssueToWork가 없으면 InventoryLedger의 ISSUE(또는 투입 이벤트)로 대체 가능한지 Discovery,
    대체 불가하면 “투입 파트 스킵” + 로그로 남김(실패 금지)

승인 데이터(HQ/CEO)
- HQ Inbox가 의미 있게:
  - 진행률/원가/보고서/출역 각각 “승인 대기” 3~5건씩 남김
- CEO 승인 대상이 존재하는 기능(T10-5-5 등)이 구현되어 있으면 1~2건 생성
  - 없으면 스킵(실패 금지)

콘솔 요약 출력(필수)
- HQ Inbox URL(가능하면)
- CEO Approvals 샘플 URL 3개(가능하면)
- FIELD “승인 완료 목록”이 채워졌음을 확인할 수 있는 힌트 출력

Done 기준
- FIELD/HQ/CEO 화면에서 “운영 데이터가 쌓인 느낌”이 분명히 확인됨
- 승인 대기/반려/승인 완료가 섞여있고, 첨부 인라인 확인 가능
