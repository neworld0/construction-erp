[FAST-CODEX] DEMO-3SITES-E2E: 3개 현장 가상 데이터(프로젝트 등록→운영→승인→월마감→정정) 시나리오 + 자동 데이터 입력(Seed) + 데이터 정합성 점검용 케이스 생성

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 현재까지 구현된 모델/URL/권한/승인/마감(CLOSE-1~4)/정정(CLOSE-3)/첨부(ATT-1~5)/재고(INV-1~4)/출역(LAB-1~4)/CBS(CBS-*) 구조를 그대로 사용
- DB 스키마 변경 금지(데모 데이터만 추가)
- 목표는 “운영 프로세스 + 데이터 정합성 점검”을 위해,
  3개 현장이 실제로 돌아가는 듯한 데이터를 프로젝트 등록부터 마감까지 한 번에 넣는 것
- 산출물:
  1) seed 스크립트 1개(또는 management command 1개)로 일괄 생성
  2) 생성된 데이터로 따라갈 수 있는 E2E 운영 시나리오 문서 1개(docs/DEMO_3SITES_E2E.md)
  3) 데이터 정합성 점검(마감/정정/승인/첨부/재고/출역) 체크리스트 포함

------------------------------------------------------------
0) 시나리오 기본 설정(하드코딩 가능, 추후 수정 쉬움)
------------------------------------------------------------
- 기준 월: 2026-02 (2월) 1개월 운영 후 1월 월마감 → 2월 초 정정 2건 발생
- 회사 성격: 조경 주력(토목 30 / 조경 60 / 건축 10 비중)
- 프로젝트(현장) 3개:
  P1: "ASAN-조경1: 공원 리모델링(조경 중심)"
  P2: "ASAN-토목1: 우수관 정비(토목+조경)"
  P3: "ASAN-건축1: 관리동 증축(소규모)"

- 계약(매출) 금액(예시):
  P1: 3,000,000,000
  P2: 2,000,000,000
  P3: 800,000,000

- 기간(예시):
  공통 착공: 2026-01-01
  준공: P1=2026-12-31, P2=2026-09-30, P3=2026-04-30

- 창고:
  본사: "HQ-WH"
  현장창고: "P1-WH", "P2-WH", "P3-WH"

- 품목(ItemMaster) 최소 20개(조경 중심) 생성 + 단위/규격 포함
  예: 잔디롤, 수목(느티/이팝), 배수관, 보도블록, 경계석, 토사/골재, 비료, 멀칭재, 안전휀스 등

- CBS(기존 로더가 있다면)에서 일부 코드 사용:
  조경 공종 위주로 30~50개 참조하여 예산/원가/투입에 연결
  (잠김/별칭/비활성 정책은 기존 규칙 준수)

- 인력/직종(LAB):
  직종 6~8개(조경반장, 조경공, 굴삭기사, 덤프기사, 신호수, 안전관리, 현장관리 등)
  단가표 생성
  급여 배부(PayrollAllocation)는 2월 기준으로 HQ에서 입력

------------------------------------------------------------
1) 구현: 데모 데이터 생성 관리 커맨드(필수)
------------------------------------------------------------
1.1 새 management command 추가
- 예: core/management/commands/seed_demo_3sites_e2e.py
- 실행:
  python manage.py seed_demo_3sites_e2e --month 2026-02 --reset (선택)

1.2 생성 항목(순서 고정)
A) 사용자/권한/2FA 정책은 기존 seed_initial 그대로 사용(있으면 재사용)
- CEO 1명, HQ 2명, FIELD(현장) 3~6명
- FIELD는 프로젝트 배정(Assignment)되어야 함(RBAC 준수)

B) 마스터 데이터
- Warehouse/Location 생성(HQ + 3개 현장)
- ItemMaster 20개 이상 생성
- LaborRole/단가표 생성
- CBS는 기존 로더/테이블을 그대로 사용하되, 예산 항목에 필요한 코드가 없으면 최소 추가(단, DB 스키마 변경 금지)

C) 프로젝트 등록(HQ)
- 각 프로젝트에 대해:
  - Project 생성(현장명)
  - ProjectContract 생성(계약금액/기간)
  - WBS baseline v1 생성(기본 공정표) + CEO 승인 상태(가능하면 APPROVED로)
  - BudgetItem 생성(프로젝트별 예산, CBS별로 10~20라인 이상)
  - 필수 첨부(계약서 파일) 1개 이상: 테스트용 더미 파일 생성하여 첨부 연결
    - 실제 파일이 필요하면 최소 크기의 텍스트/pdf 더미 파일을 코드로 생성

D) 운영 데이터(1월~2월 5일까지)
- 각 프로젝트별로 기간 중 매월 8~12일치 운영 데이터 생성(주 2~3회 입력 느낌)
  1) 진행률(Progress)
     - DRAFT→SUBMITTED→APPROVED 흐름이 섞이도록(일부는 반려 후 재제출)
     - 각 Progress에 사진 첨부 1~3개(이미지 더미 파일) 포함
  2) 보고서(Report)
     - 같은 날짜에 2건 이상 발생하는 날 포함(요구사항 반영)
     - DRAFT/REJECTED 상태에서 첨부 교체 케이스 1회 포함(ATT 정책 점검)
  3) 원가(Cost)
     - 같은 날짜에 여러 건 발생(재료비/장비임대/외주 등)
     - 일부는 증빙 첨부(영수증/거래명세서 더미 파일)
  4) 출역부(Timesheet)
     - 현장별 6~10일치, 직종별 인원/시간/일수 기록
     - HQ 승인 흐름 포함(일부 반려 후 수정)
  5) 재고(INV)
     - HQ 창고에 입고(구매/수불) 5~10건
     - 본사→현장 이동(Transfer) 3~6건
     - IssueToWork로 현장 투입 3~6건 생성, CBS/원가 자동 집계 연결

E) 승인 데이터
- HQ 승인 Inbox가 의미 있게 보이도록:
  - 진행률/원가/보고서/출역 각각 승인 대기 3~5건씩 존재하도록
  - CEO 승인 대상(설계변경/WBS변경/패키지승인 등 T10-5-5 구현분)이 있다면 1~2건 생성

F) 월 마감(CLOSE-1)
- 2026-01 ClosingPeriod 생성
- 월말(2026-01-31) 기준으로 마감 실행:
  - 마감 전까지 승인된 건은 KPI에 포함
  - 마감 후에는 입력/수정 차단(CLOSE-2 확인)

G) 정정(CLOSE-3)
- 마감 후(2026-02-02~03) 정정 2건 생성:
  - 정정 1: P1 원가 누락분(예: 장비 임대료) → CEO 승인 후 KPI 반영
  - 정정 2: P2 출역부 누락분/급여배부 수정 → CEO 승인 후 KPI 반영
- 정정은 “마감 후 수정 대신 정정분 생성” 원칙 준수
- 정정 승인/반영 이력 표시가 있으면 같이 생성

------------------------------------------------------------
2) 데이터 정합성 점검을 위한 “의도적 오류/리스크 케이스” 6종 포함(필수)
------------------------------------------------------------
아래 케이스를 일부러 섞어 넣고, Risk/Evidence/품질배지가 어떻게 반응하는지 점검 가능하게 한다.

R1) 진행률 1건: 첨부 없음 + 제출만 됨(미정/추정 배지 확인)
R2) 원가 1건: 제출됐지만 증빙 첨부 누락(리스크 카드 유도)
R3) 보고서 1건: 반려 후 첨부 교체 + 재제출(ATT 정책 확인)
R4) 출역 1건: 승인 대기 상태로 월마감 직전까지 남김(마감 전 경고/미정 표시)
R5) 마감 후 입력 시도용: 마감된 2월에 DRAFT 1건 생성 시도 → 저장이 막히거나 정정 안내가 나와야 함(가능하면 테스트 코드로 확인)
R6) 재고 이동: HQ→현장 Transfer는 있었는데 투입/원가 연결이 없어서 잔량이 남는 케이스(재고/원가 정합 체크)

------------------------------------------------------------
3) 생성 후 “E2E 운영 시나리오 문서” 자동 생성(필수)
------------------------------------------------------------
docs/DEMO_3SITES_E2E.md 생성(또는 업데이트) 내용:
- 3개 현장 개요(계약/기간/예산 요약)
- FIELD 일일 운영 플로우(진행률/보고서/원가/출역) + DRAFT→SUBMITTED
- HQ 승인 Inbox에서 처리 순서(진행률→원가→출역→보고서) + 반려/재제출 케이스 설명
- CEO 승인 상세(/app/ceo/approvals/<id>/)에서 첨부 인라인 확인 포인트(ATT-3)
- 월 마감 실행 절차(HQ): ClosingPeriod OPEN→CLOSED
- 마감 이후 정정(Adjustment) 생성 및 CEO 승인 흐름
- KPI/품질배지/리스크 카드가 어디서 확인되는지(화면 URL 포함)
- “데이터 정합성 점검 체크리스트” 포함:
  - 제출 후 수정 불가/반려 후 수정 가능/마감 후 차단/정정만 허용 등

------------------------------------------------------------
4) 실행/검증 방법(필수)
------------------------------------------------------------
- 커맨드 실행:
  python manage.py seed_demo_3sites_e2e --month 2026-01
- 생성된 계정/프로젝트/승인건을 출력(콘솔에 요약 로그):
  - 프로젝트 id/URL
  - FIELD 계정별 로그인 후 볼 프로젝트
  - HQ Inbox URL
  - CEO 승인 상세 URL 샘플 3개
  - 마감/정정 샘플 URL

- 최소 검증 스크립트(가능하면 pytest 3~5개)
  - 마감 후 수정 차단(assert 403 or blocked)
  - REJECTED 상태 첨부 수정 허용(assert ok)
  - SUBMITTED 상태 첨부 수정 차단(assert blocked)
  - 목록 배지 count가 실제 첨부 수와 일치
