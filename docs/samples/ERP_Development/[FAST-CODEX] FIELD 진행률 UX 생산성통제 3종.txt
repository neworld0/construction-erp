[FAST-CODEX] FIELD 진행률 UX 생산성/통제 3종 (어제 값 복사 + 프로젝트 자동선택/로드 개선 + 날짜 선택 잠금)

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 기존 설계/URL/모델 유지
- 대상: FIELD 진행률 탭(모바일 우선, PC 공통)
- DB 스키마 변경 없이 구현
- 기존 RBAC/Approval/Closing/AuditLog/Risk Engine 로직 변경 금지
- “제출 후 수정 불가” 및 “마감 후 입력/수정 차단(CLOSE-2)” 정책은 그대로 존중

목표(3가지)
4) “어제 값 복사” 버튼 추가: 전일 진행률/메모를 오늘 입력 폼으로 자동 복사
5) 프로젝트 선택 + 로드 UX 개선: 최근 프로젝트 자동선택 + 프로젝트 변경시에만 로드
6) 날짜 필드 잠금(기본 ON): 기본 오늘, 어제까지만 선택, 그 이전은 HQ 요청(차단)

------------------------------------------------------------
4) “어제 값 복사” 버튼 (진행률 입력 상단)
------------------------------------------------------------
요구사항
- 위치: 진행률 입력 폼(작업/WBS 선택 영역) 상단에 작은 버튼
  버튼 라벨: “어제 값 복사”
- 동작:
  - 현재 선택된 프로젝트 + 선택된 WBS(또는 작업 항목) 기준으로
    “어제 날짜”의 진행률 값과 메모를 조회하여
    오늘 폼의 progress_input + memo_input에 채운다.
  - 복사 후, 사용자는 숫자(progress)만 조정해 제출 가능
    (메모도 수정 가능하게 두되, UX 안내 문구로 ‘필요 시 수정’ 표시)
- 예외 처리:
  - 어제 데이터가 없으면:
    - 토스트/인라인 메시지: “어제 입력값이 없습니다.”
    - 폼 값은 변경하지 않음
  - 어제 값이 제출/승인된 건이어도 “읽기”는 가능(복사는 가능)
- 보안/권한:
  - FIELD는 본인/배정 프로젝트 범위 내 데이터만 조회
- 감사:
  - 복사 자체는 저장이 아니므로 AuditLog 불필요(저장/제출 시 기존 로그만)

구현 상세
A) 데이터 소스 Discovery(필수)
- 진행률 저장 모델/테이블(예: ProgressEntry/WBSProgress/DailyReportLine 등)에서
  “프로젝트 + WBS + 날짜”로 조회 가능한지 확인한다.
- 어제 값 조회는 1건만 반환:
  - 우선순위: (1) 제출/승인 최신 1건, (2) 임시저장 최신 1건
  - 정렬 기준: updated_at desc

B) API/뷰(권장: JSON endpoint 1개)
- 신규 endpoint (예):
  - GET /app/field/progress/yesterday/?project_id=..&wbs_id=..&date=YYYY-MM-DD
- 응답:
  - { ok: true, progress: "9.0", memo: "...", source_date:"YYYY-MM-DD" }
  - 없으면 { ok:false, message:"..." }
- 서버에서 RBAC 체크 필수

C) 프론트(JS)
- “어제 값 복사” 클릭:
  - project_id / wbs_id 선택 여부 확인
  - endpoint 호출(fetch)
  - 성공 시:
    - progress_input.value = progress (이미 1자리 정규화 로직이 있으면 그대로 통과)
    - memo_input.value = memo
    - 메시지: “어제 값이 복사되었습니다. 진행률을 확인 후 제출하세요.”
  - 실패 시 메시지 표시

------------------------------------------------------------
5) 프로젝트 선택 + 로드 UX 개선 (최근 프로젝트 자동선택 + 변경시에만 로드)
------------------------------------------------------------
요구사항
- 기본: 최근 사용 프로젝트를 자동 선택한다.
- “로드” 버튼은 프로젝트 변경시에만 필요(또는 자동 로드로 대체)
- 현장 UX:
  - 프로젝트 드롭다운 변경 시 자동으로 데이터가 로드되거나,
  - 최소한 변경 감지 후 “로드” 버튼이 활성화되게 한다.

구현 상세(스키마 변경 없이)
A) “최근 프로젝트 기억” 방식(우선순위)
1) 세션(session) 저장 (권장, 서버측)
   - last_project_id를 session에 저장
   - FIELD 홈 진입 시 last_project_id가 있으면 기본 선택
2) 로컬스토리지(localStorage) (대안, 프론트)
   - lastProjectId 키로 저장/복원
3) 쿠키 (차선)

B) 로드 UX
- 옵션 1(권장): 프로젝트 변경 시 자동 로드
  - 드롭다운 onchange 이벤트 → 페이지 리다이렉트(쿼리스트링 project_id=) 또는 ajax로 데이터 갱신
  - 기존 구현이 server-render라면 “리다이렉트 방식”이 안전
- 옵션 2: 로드 버튼은 유지하되
  - (기본 진입) last_project로 자동 로드되어 버튼 없이도 사용 가능
  - 프로젝트 변경 시에만 “로드” 버튼이 강조/활성화

C) 권한
- FIELD는 배정된 프로젝트만 드롭다운에 표시(이미 있으면 유지)

완료 기준
- FIELD가 /app/field/ 재접속 시 마지막 프로젝트가 자동 선택/로드된다.
- 프로젝트가 바뀌지 않으면 ‘로드’ 버튼 없이도 바로 입력 가능하다.

------------------------------------------------------------
6) 날짜 필드 잠금 옵션 (기본 ON)
------------------------------------------------------------
정책(필수)
- 기본값: 오늘
- 선택 가능 범위: 오늘 또는 어제(“어제까지만”)
- 그 이전 날짜(2일 전~)는 FIELD에서 선택 불가(차단)
- 단, 기존 데이터 조회(읽기)는 가능하되, 입력/임시저장/제출은 차단
- 사유 안내:
  - “소급 입력은 HQ 요청이 필요합니다.”

구현 상세
A) 프론트 가드
- date input에 min/max 설정:
  - max = today
  - min = yesterday (또는 allowed_min = yesterday)
- UI에서 그 이전 날짜 선택 시도:
  - 즉시 되돌리고 안내 메시지 표시

B) 서버 가드(필수)
- 임시저장/제출 요청에서 date 검증:
  - if date < (today - 1 day): reject
  - message: “소급 입력은 HQ 요청이 필요합니다. (허용: 오늘/어제)”
- 마감(CLOSE) 정책과 충돌 시:
  - CLOSE-2가 더 강함(마감이면 오늘/어제라도 차단)

C) HQ 요청 흐름(이번 티켓 범위 밖)
- 이 티켓에서는 “차단 + 안내”까지만 구현
- 별도 티켓으로 HQ가 소급 입력 허용(override) 워크플로우를 만들 수 있음(지금은 제외)

------------------------------------------------------------
파일/위치 Discovery 지시(필수)
- FIELD 진행률 탭 템플릿/뷰 파일 확인:
  - templates/field/dashboard.html 또는 field/progress.html
  - field/views.py progress handlers
- 프로젝트 선택/로드 로직이 있는 위치 확인:
  - querystring project_id 사용 여부
  - session 사용 여부
- 진행률 모델에서 “date” 필드와 조회 조건 확인

완료 기준(Acceptance)
- “어제 값 복사” 버튼이 진행률 입력 상단에 보이고, 어제 값이 있으면 progress+memo가 채워진다.
- 최근 사용 프로젝트가 자동 선택되고, 프로젝트 변경시에만 로드가 필요(또는 자동 로드)하다.
- 날짜는 기본 오늘이며, FIELD는 오늘/어제만 입력 가능하고 그 이전은 임시저장/제출이 차단된다(서버/프론트 모두).
- DB 스키마 변경 없이, 기존 권한/마감/승인 로직을 깨지지 않게 유지한다.

간단 테스트
- 케이스1: 어제 동일 프로젝트+WBS 입력 존재 → “어제 값 복사” → 값 채워짐
- 케이스2: 어제 값 없음 → 메시지 + 값 변화 없음
- 케이스3: 재접속 시 last 프로젝트 자동 선택됨
- 케이스4: 2일 전 날짜 선택 → 프론트에서 차단 + 서버 제출도 거부

기존 구조를 최대한 재사용하여 최소 변경으로 기능을 추가하세요.
