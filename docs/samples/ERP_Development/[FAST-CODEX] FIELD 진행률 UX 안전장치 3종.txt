[FAST-CODEX] FIELD 진행률 UX 안전장치 3종 (입력 가드 + 제출 확인 모달 + 상태 뱃지 통일)

당신은 시니어 Django 엔지니어입니다. 리포지토리 루트는 construction-erp 입니다. 

전제
- 기존 설계/URL/모델 유지
- 대상 화면: FIELD 진행률 탭(모바일/PC 공통, 모바일 우선)
- DB 스키마 변경 없이 구현(필드 타입 변경 금지)
- 기존 “임시저장 → 제출 → (HQ 승인)” 플로우 유지
- 제출 후 수정 불가 정책은 이미 존재(또는 CLOSE-2/제출 차단 로직)하므로 그대로 존중

목표(3가지)
1) 진행률(%) 입력 필드 가드: 0~100 강제 + 소수점 자릿수 고정 + % 표시
2) 제출 버튼 클릭 시 “최종 확인 모달” 추가(제출 후 수정 불가 경고 + 요약)
3) 승인 상태 색상 + 아이콘 통일(임시저장/제출/승인/반려)

------------------------------------------------------------
1) 진행률(%) 입력 필드 가드 추가
------------------------------------------------------------
요구사항
- 입력 범위: 0.0 ~ 100.0
- 소수점: 1자리 고정(기본) + 내부적으로 Decimal/Float 저장은 기존 그대로(단, 표시/검증을 1자리로 통일)
- 입력 UX:
  - 모바일 numeric keypad 유도
  - 필드 오른쪽에 “%” 단위 고정 표시
  - placeholder 예: “0.0”
- 사용자 입력 혼선 방지:
  - “9”, “9.0”, “9.000” 등 입력은 모두 “9.0”으로 normalize
  - “90” 입력은 정상(90.0)
  - “900” 등 100 초과 입력 시 즉시 에러 표시 + 저장/제출 차단

구현 상세
A) 프론트(템플릿)
- 진행률 input에:
  - type="number"
  - inputmode="decimal"
  - min="0" max="100"
  - step="0.1"
- % 단위 표시:
  - input-group 형태로 [ input ][ % ] 구성 (Bootstrap이면 input-group-append 사용)
- 에러 메시지 영역(인라인):
  - “진행률은 0~100 사이 숫자여야 합니다. (예: 9.0)”

B) JS 정규화(권장, 최소 구현)
- blur(포커스 아웃) 시:
  - 빈 값이면 그대로
  - parseFloat 후 NaN이면 에러
  - 0~100 clamp 금지(사용자 실수 숨기지 말고 에러로 막기)
  - toFixed(1)로 표시 문자열 교정 → input.value 업데이트
- 제출/임시저장 클릭 시:
  - validateProgress() 통과 못 하면 submit 막고 에러 포커스

C) 서버 검증(필수)
- 기존 form/view에서 progress 값 검증 추가:
  - 0 <= value <= 100
  - 소수점 1자리로 quantize(가능하면) 또는 round(1) 적용
- 검증 실패 시:
  - 임시저장/제출 모두 막고, 에러 메시지 렌더

주의
- DB 타입 변경 금지(DecimalField 자리수 변경/마이그레이션 금지)
- 다만 저장 시 round(1)만 적용해 데이터 일관성 확보

------------------------------------------------------------
2) 제출 버튼 “최종 확인 모달” 추가
------------------------------------------------------------
요구사항
- 진행률 “제출” 클릭 시 모달 표시(임시저장은 모달 없이 저장)
- 모달 내용(템플릿):
  제목: “제출 확인”
  본문: “이 진행률은 제출 후 수정할 수 없습니다.”
  요약:
    - 작업: {wbs_name}
    - 진행률: {progress_display}%
    - 날짜: {date_display}
  버튼: [취소] [제출]
- [제출] 버튼을 눌러야 실제 제출 요청이 서버로 전송됨
- 이미 제출된 항목이면:
  - 제출 버튼 숨김/비활성(기존 정책 유지)

구현 상세
A) 템플릿에 모달 마크업 추가
- Bootstrap modal 사용(프로젝트에 Bootstrap이 이미 있으면 그대로)
- 모달은 진행률 탭에 1개만 둔다(행마다 모달 생성 금지)

B) JS 연결
- “제출” 버튼 클릭:
  - validateProgress() 먼저 수행
  - 요약 텍스트를 모달에 주입:
    - wbs 라벨(text)
    - progress input value (이미 1자리 정규화된 값)
    - date(오늘)
  - 모달 show
- 모달의 최종 [제출] 버튼:
  - 실제 form submit 트리거 또는 fetch/POST 호출(현재 제출 구현 방식 유지)
  - 중복 클릭 방지(disable 처리)

------------------------------------------------------------
3) 승인 상태 색상 + 아이콘 통일
------------------------------------------------------------
요구사항(표준)
- 임시저장: 회색, 📝
- 제출: 파랑, 📤
- 승인: 초록, ✅
- 반려: 빨강, ❌
- 상태는 “텍스트” + “뱃지”로 함께 표시(모바일은 뱃지 우선)
- 진행률 탭의 “최근 입력 목록” 또는 항목 카드에 동일 규칙 적용

구현 상세
A) 상태 매핑 함수/템플릿 필터(권장)
- Python helper 또는 template filter로:
  input: status code
  output: {label_ko, icon, badge_class}
- badge_class 예:
  - draft: badge-secondary
  - submitted: badge-primary
  - approved: badge-success
  - rejected: badge-danger

B) 목록 UI 적용
- 각 행/카드 좌측에 뱃지 배치:
  [📝 임시저장] / [📤 제출] / [✅ 승인] / [❌ 반려]
- 기존 “approved 텍스트 👍”는 제거 또는 승인 상태에서만 보조로 유지(권장: 제거)

------------------------------------------------------------
파일/위치 Discovery 지시(필수)
- FIELD 진행률 탭 템플릿 파일과 view를 먼저 찾는다:
  - 예: templates/field/dashboard.html (진행률 탭 포함)
  - 또는 templates/field/progress.html
- 진행률 저장/제출 처리 view:
  - field/views.py 내 progress 관련 핸들러
- 최근 입력 목록 렌더링 위치:
  - 진행률 탭 내 리스트 block

완료 기준(Acceptance)
1) 진행률 입력이 0~100 범위 밖이면 임시저장/제출이 막힌다.
2) 진행률 입력이 blur 시 1자리(예: 9.0)로 자동 정규화된다.
3) 제출 클릭 시 최종 확인 모달이 뜨고, 모달에서 제출해야만 실제 제출된다.
4) 제출 후 수정 불가 정책이 UI에서도 명확하다(제출 버튼 숨김/비활성 + 메시지).
5) 목록 상태 뱃지가 표준(회색/파랑/초록/빨강 + 아이콘)으로 통일된다.

간단 테스트
- 9 입력 → blur 후 9.0 표시
- 9.000 입력 → blur 후 9.0 표시
- -1 / 101 입력 → 에러 + 저장/제출 차단
- 제출 클릭 → 모달에 작업/진행률/날짜 요약 표시 → 확인 제출 시 SUBMITTED로 변경
- 목록에서 임시저장/제출/승인/반려가 색+아이콘으로 일관 표시
