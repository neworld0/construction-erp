=====================================================
[INV-5 목표]
=====================================================
현장에서 자재를 “작업(공정/공종) 투입” 처리하면,
1) 재고는 즉시 감소(원장 기록)
2) 해당 투입은 CBS(비목/공종)로 연결되고
3) 원가 실적(CostActual)을 자동 생성/집계하여 KPI에 반영되도록 한다.

핵심 정책:
- 재고 변동은 INV-3 InventoryLedger로만 처리(직접 Stock 수정 금지)
- CostActual 자동 생성은 “원장 기반 증빙”이므로
  승인/잠금/마감 규칙(CLOSE-2)과 정합성을 유지해야 한다.
- 같은 날에 여러 건 투입 가능
- 현장(FIELD)은 본인 프로젝트(SITE 창고)만 투입 가능
- HQ는 조회/검토/승인(기존 승인흐름)만 담당(필요시 HQ 대리투입 허용 옵션)

=====================================================
0) Discovery (필수)
=====================================================
아래를 먼저 확인하고 실제 모델/필드명에 맞춰 구현하라.
1) CostActual 모델 필드:
   - project, date(spent_date), amount, memo, status(승인상태), created_by 등
2) CBS(CostItem) 모델/필드:
   - code, name, is_active, locked/alias 정책
3) Evidence(원가 증빙 업로드) 연계 방식(object_type/object_id)
4) InventoryLedger 생성 서비스(create_ledger_entry)와 ref_type 사용 방식
5) FIELD 탭 구조(진행률/보고서/원가) 및 일일보고(DailyReport) 연계 방식
6) CLOSE-2 가드(assert_month_open) 위치
Discovery 결과를 코드 주석으로 남기고 “기준일(date) 필드 매핑”을 명확히 적어라.

=====================================================
1) 개념/데이터 흐름 (정답 루트)
=====================================================
IssueToWork(투입) 1건 = “해당 날짜/현장창고에서 특정 품목을 특정 CBS에 투입한 기록”

처리 시 생성되는 것:
A) InventoryLedger 1건(또는 라인별 N건) — qty 감소(출고)
B) CostActual 1건(또는 라인별 N건) — 금액 증가(원가 실적)

금액 산정 방식(MVP):
- unit_cost가 원장에 기록되어 있으면 사용
- 없으면:
  - ItemMaster에 standard_cost(표준단가)가 있으면 사용(이번 티켓에서 필드 추가 가능)
  - 둘 다 없으면 “금액 미정(0)”으로 생성 + data_quality=ESTIMATED 표기(후속 개선)
=> 운영상 최소한 standard_cost를 ItemMaster에 추가하는 방향을 권장(아래 2)

=====================================================
2) 모델 설계 (필수)
=====================================================
apps/inventory/models.py 또는 apps/inventory/issue_models.py

[ItemMaster 확장(권장, 최소)]
- standard_cost (IntegerField, null=True, blank=True)  # 원/기본단위
- cost_updated_at (DateTimeField, null=True, blank=True)

[IssueToWork]
- id
- issue_no (CharField, unique, db_index=True)   # IW-YYYYMM-0001
- project (FK Project)
- warehouse (FK Warehouse)        # SITE warehouse 고정(현장)
- location (FK Location, null=True, blank=True)
- issue_date (DateField)          # 업무 기준일(마감 체크 기준)
- status (choices):
    "DRAFT"       # 임시저장
    "SUBMITTED"   # 제출(현장 제출)
    "APPROVED"    # HQ 승인(선택: 기존 승인 시스템 연계)
    "REJECTED"    # 반려
- note (TextField, blank=True)
- created_by (FK User)
- submitted_at/approved_at/approved_by
- created_at/updated_at

[IssueToWorkLine]
- id
- issue (FK IssueToWork, related_name="lines")
- item (FK ItemMaster)
- qty (DecimalField(18,3))
- uom (FK UoM)  # item.uom 동일 강제
- cbs (FK CostItem)   # CBS 선택(필수)
- unit_cost (IntegerField, null=True, blank=True)  # 당시 단가(스냅샷)
- amount (IntegerField, null=True, blank=True)     # qty*unit_cost
- memo (CharField, blank=True)

제약:
- qty > 0
- cbs는 active=True만 선택 가능
- cbs locked/alias/비활성 정책:
  - FIELD에서 inactive/locked CBS는 선택 불가(정책대로)
  - alias가 있으면 표시(label)에는 alias 포함

번호 생성:
- IssueNumberSequence(key="IW-YYYYMM", last_number) select_for_update

=====================================================
3) 처리 로직(핵심): 제출 시 자동 생성
=====================================================
원칙:
- DRAFT 저장은 DB에만 저장(재고/원가 반영 X)
- SUBMITTED(제출) 시점에:
  - 마감 체크(assert_month_open(issue_date))
  - 재고 차감 원장 생성
  - CostActual 생성
  - Evidence 연계가 있으면 “원장/원가 자동생성”을 참조하는 evidence 객체 생성(선택)

처리 방법:
- services.py에 submit_issue_to_work(issue_id, actor) 구현
- transaction.atomic으로 아래를 한 번에 처리:
  1) 상태 확인(DRAFT만 제출 가능)
  2) CLOSE-2 마감 체크
  3) 각 line에 대해:
     a) 단가 결정:
        - line.unit_cost 있으면 사용
        - 없으면 item.standard_cost 사용
        - 그래도 없으면 unit_cost=0, quality=ESTIMATED 플래그
     b) amount = round(qty * unit_cost) (정수 원)
     c) InventoryLedger 생성:
        - tx_type="ISSUE"
        - tx_date=issue_date
        - warehouse/location
        - qty_delta = -qty
        - unit_cost, amount 기록
        - ref_type="ISSUE_TO_WORK", ref_id=IssueToWork.id
        - note에 issue_no/cbs 코드 포함(추적성)
     d) CostActual 생성(권장: line당 1건):
        - project=issue.project
        - date=issue_date
        - cbs=line.cbs
        - amount=amount
        - memo = "[자재투입] {item.code} {item.name} {qty}{uom} (IW-...)" + line.memo
        - source_type="ISSUE_TO_WORK"(필드가 있으면), source_id=line.id
        - status는 기존 원가 제출/승인 정책에 맞춤:
           * 제출 즉시 HQ 승인 대상이면 SUBMITTED 상태로 생성
           * 또는 APPROVAL_REQUEST 자동 생성(후속)
  4) IssueToWork.status="SUBMITTED", submitted_at 기록
  5) AuditLog 기록

주의:
- 재고 부족 시 제출 실패(음수 재고 금지 정책 준수)
- 부분 성공 금지(atomic)

=====================================================
4) 승인 연계(선택, 운영 옵션)
=====================================================
옵션 A(최소, MVP):
- IssueToWork 제출(SUBMITTED)만 구현
- HQ는 기존 “원가 승인” 흐름으로 CostActual을 승인
- IssueToWork 자체는 상태를 SUBMITTED로 유지(또는 CostActual 승인 완료 시 자동 APPROVED로 올림 — 후속)

옵션 B(정합성 강화, 권장):
- IssueToWork 제출 시 ApprovalRequest 생성(object_type="ISSUE_TO_WORK")
- CEO/HQ 승인 시 IssueToWork.status=APPROVED로 전환
- 단, 이미 재고/원가 반영은 제출 시점에 되었으므로
  승인 반려 시에는 “취소/상쇄”가 필요(복잡)
=> 이번 티켓은 옵션 A로 가고, 옵션 B는 후속 티켓으로 TODO 처리.

5) API (필수)
=====================================================
- GET  /api/inventory/issues/?project=&status=&start=&end=&q=
- POST /api/inventory/issues/                 # create DRAFT + lines
- PATCH /api/inventory/issues/<id>/           # DRAFT 수정
- POST /api/inventory/issues/<id>/submit/     # 제출(자동 원장+원가 생성)
- GET  /api/inventory/issues/<id>/

권한:
- FIELD: 본인 프로젝트만 CRUD + submit
- HQ/CEO: 조회 가능(필터/검색), 수정은 금지(또는 제한)

응답에 포함:
- issue_no, status, issue_date, lines
- submit 응답에는 생성된 ledger_ids / cost_actual_ids 요약 포함(선택)

=====================================================
7) 마감(CLOSE-2) 연계 (필수)
=====================================================
- IssueToWork.submit은 issue_date 기준 월이 CLOSED면 차단
- DRAFT 저장도 운영상 혼란 방지를 위해:
  - CLOSED 월에는 DRAFT 생성 자체를 차단(권장) 또는 생성은 허용하되 submit 불가
  - 이번 티켓에서는 “생성도 차단”으로 단순화(운영 안전)
메시지:
"YYYY년 M월은 마감되었습니다. 마감월 자재 투입은 정정 절차로 처리해야 합니다."

=====================================================
8) CBS 정책 연동(필수)
=====================================================
- FIELD CBS 선택:
  - active=False는 검색 결과에서 제외
  - locked CBS는 선택 불가(또는 alias만 허용) — 프로젝트에서 적용 중인 정책을 그대로 따른다.
- 표시 라벨:
  - "CBS코드 | 이름(별칭: ...)" 형태

=====================================================
9) AuditLog (필수)
=====================================================
이벤트:
- ISSUE_TO_WORK_CREATE (DRAFT)
- ISSUE_TO_WORK_UPDATE (DRAFT)
- ISSUE_TO_WORK_SUBMIT
- ISSUE_TO_WORK_BLOCKED_CLOSED (선택)

metadata:
{issue_id, issue_no, project_id, issue_date, line_count, total_amount}

=====================================================
10) 테스트 시나리오 (필수)
=====================================================
1) FIELD가 DRAFT 생성(라인 2개) → 성공, 재고 변동 없음
2) submit:
   - 재고 충분 → InventoryLedger(-) 생성 + Stock 감소
   - CostActual 생성(라인별) + 금액 합계 일치
   - status=SUBMITTED, 이후 수정 불가
3) 재고 부족 → submit 실패, 원장/원가 생성 없음(atomic)
4) CLOSED 월(issue_date) → 생성/submit 차단
5) CBS inactive/locked → 선택/submit 불가
6) 권한:
   - FIELD는 타 프로젝트 issue 접근 불가(403)
   - HQ는 조회 가능

=====================================================
완료 기준(DoD)
=====================================================
- IssueToWork/Line 모델 + 마이그레이션 완료
- DRAFT/임시저장 + 제출(submit) 구현
- submit 시 InventoryLedger와 CostActual이 자동 생성되고 atomic 보장
- 재고 부족/마감월/권한/CBS 정책 위반 시 차단
- AuditLog 기록
- KPI/집계는 기존 CostActual 기반이므로 자동으로 반영(추가 수정 최소)
